# 异常状态检测规则清单（Anomaly Detection Rules — 审核稿）

| 项目 | 内容 |
|---|---|
| 文档编号 | RSS-002 |
| 版本 | v0.1（**审核稿，待你确认**） |
| 用途 | **仅整理"什么情况算异常"的判据**，供审核 |
| 上位文档 | `docs/safety_rules_spec.md`（RSS-001，含响应/恢复/PL 分配） |
| 判据条数 | 76 条检测判据（另有 11 条非检测类，见 §6） |
| 审核方式 | 逐条确认：**判据是否合理 / 阈值是否恰当 / 前置条件是否漏 / 是否与别的判据重复** |

> **为什么先审判据**：判据错了两件事都会发生——**漏检**（该报的没报）和**误报**（不该报的报了）。误报同样致命：告警疲劳会让操作员关掉安全系统。所以判据必须逐条审。

## 0. 审核前必读：5 个关键结论

### 结论 1：判据分三类，混在一起会出错

| 类型 | 回答的问题 | 失效模式 | 典型规则 |
|---|---|---|---|
| **时间类** | 数据来没来？ | 漏检（数据冻结但仍"按时"到达） | `SEN-001` `LOC-005` `CMD-007` |
| **变化类** | 数据变没变？ | **误报**（机器人静止时读数本就不变） | `SEN-003` `SEN-004` `LOC-007` |
| **语义类** | 数据讲不讲得通？ | 漏检（NaN 静默通过比较） | `SEN-011` `COL-005` `LOC-009` |

**变化类判据是最容易做错的**——必须带前置条件（见 §3）。`SEN-006` 就是专门为此设的抑制规则。

### 结论 2：三类判据必须交叉，单一判据抓不到静默失效

`/amcl_pose` 以 10 Hz 正常发布、协方差正常、数值合法、时间戳单调——**但位姿已经偏了 40 cm**。
时间类和语义类判据全部通过。**只有跨源交叉校验能抓到**：`LOC-006`（定位 vs 里程计）、`LOC-009`（长期漂移）、`LOC-007`（数值冻结）。
跨源复合判据共 9 条，见 §2.4——**这组是审核重点**。

### 结论 3：必须区分"判据未成立"与"无法判定"

| 情况 | 错误做法 | 正确做法 |
|---|---|---|
| 机器人静止，激光读数不变 | 报 `SEN_STUCK` | 抑制（`SEN-006`：不成立） |
| 没有里程计，无法比对指令 | 报"指令不一致" | 报 `valid = false`（无法判定） |
| 传感器从未收到数据 | 当作正常 | 按 `UNKNOWN` = **不可信**处理 |

现有实现的 `command.valid` / `consistent` 三态设计已经处理了第二行——**这个模式必须推广到所有跨源判据**。

### 结论 4：3 条判据的阈值与平台实际不符（必须先改）

| 判据 | 现值 | 问题 | 建议 |
|---|---|---|---|
| `SEN-001` scan 超时 | 1.0 s | 激光实际 5 Hz（周期 0.2 s），允许丢 5 帧 | **→ 0.6 s** |
| `SEN-001` imu 超时 | 1.0 s | IMU 实际 100 Hz，允许丢 100 帧 | **→ 0.05 s** |
| `COL-002` 障碍临界距离 | 0.15 m | 仿真下所需停止距离 ≈ 0.30 m，**判据成立时已撞上** | **→ 0.36 m**，并按 §7.2 重算 |

### 结论 5：有 2 组判据重复，需合并决策

| 组 | 判据 | 重复点 | 建议 |
|---|---|---|---|
| A | `MOT-012` vs `CMD-011` | 都在检测"指令说走但没走" | **合并**，或明确分工（见 §7-决策 1） |
| B | `MOT-001`/`MOT-002` vs `CMD-001` | 同一阈值判两次 | **合并**（见 §7-决策 2） |

## 2. 判据明细（含完整表达式）

> 本节给出每条判据的**精确定义**，便于直接落成代码。变量名沿用 `RobotState` 消息字段。

### 2.1 时间类判据（数据"来没来"）

**`SEN-001` / `COM-001` / `CMD-007` / `LOC-005` 数据超时**

```
异常  ⟺  (now_wall − last_wall_time)  >  timeout_sec
```

| 源 | 超时值 | 依据公式 | 现值 | 需改 |
|---|---|---|---|---|
| `/odom` | 0.10 s | `3 × T_period`（30 Hz） | 1.0 s | ✅ 改 |
| `/scan` | **0.60 s** | `3 × T_period`（5 Hz） | 1.0 s | ✅ 改 |
| `/imu` | **0.05 s** | `3 × T_period`（100 Hz） | 1.0 s | ✅ 改 |
| `/joint_states` | 0.20 s | `3 × T_period`（30 Hz） | 2.0 s | ✅ 改 |
| `/cmd_vel` | **0.50 s** | `T_cmd_wd` | 1.0 s | ✅ 改 |
| 定位源 | **0.30 s** | `3 × T_period`（10 Hz） | 缺失 | ➕ 新增 |
| `/battery` | 1.0 s | `3 × T_period` | 5.0 s | 可选 |

通用式：`timeout = max(3 × T_period, T_min)`，`T_min = 0.05 s`（防过紧误报）。

**⚠ 审核点**：`T_min = 0.05 s` 是否合适？对 100 Hz 的 IMU，`3×T_period = 0.03 s`，会被 `T_min` 抬到 0.05 s（允许丢 ~4 帧）。若要求更严，应把 `T_min` 降到 `0.02 s`，但需确认调度抖动不会造成误报。**这个值需要你根据实测调度抖动来定。**

**`SEN-002` 超时升级**

```
异常(升级)  ⟺  (now_wall − last_wall_time)  >  2 × timeout_sec
```

**`SEN-013` 采样率异常**

```
异常  ⟺  (measured_rate_hz < 0.5 × nominal_rate)  ∨  (measured_rate_hz > 2 × nominal_rate)
        持续 2.0 s
```

**`SEN-012` / `SYS-008` / `SYS-014` 时钟异常**

```
异常  ⟺  |Δstamp|         > 1.0 s      # 消息时间戳回退或跳跃
      ∨  stamp_lead       > 0.5 s      # 时间戳领先墙钟
      ∨  |wall − system|  > 1.0 s      # 墙钟与系统时钟偏差
      ∨  monotonic_skew   > 阈值       # time.time() 与 time.monotonic() 差异常
```

**`COM-002` 通信质量**

```
异常  ⟺  loss_pct > 5%  ∨  latency > 100 ms  ∨  jitter > 50 ms
```

**`COM-003` 心跳断链**

```
异常  ⟺  (now − last_heartbeat)  >  3 × T_hb        # T_hb = 100 ms
```

**`COM-010` 重放**

```
异常  ⟺  seq[k] ≤ seq[k−1]          # 序号非单调
      ∨  msg 已在 (now − 1.0 s) 窗口内出现过
```

**`SYS-003` / `SYS-004` / `SYS-005` 看门狗停滞**

```
异常(SYS-003)  ⟺  (now − last_sm_tick)   > 300 ms   ∨  进程退出
异常(SYS-004)  ⟺  (now − last_mon_pub)   > 500 ms
异常(SYS-005)  ⟺  (now − last_gate_out)  > 200 ms   ∨  门控进程停滞
```

### 2.2 变化类判据（数据"变没变"）—— **必须带前置条件**

**`SEN-003` 数值卡死**

```
前置条件:  motion_expected == true          # ← 没有这一条会大面积误报
异常      ⟺  (max(x) − min(x)) < ε_stuck    在窗口 T_stuck = 1.0 s 内

ε_stuck 按源:  odom.speed        : 1e-6 m/s
              odom.yaw          : 1e-6 rad
              imu.ang_vel_z     : 1e-6 rad/s
              joints.max_abs_vel: 1e-6
```

**`SEN-004` 激光整帧冻结**

```
异常  ⟺  连续 N_frozen = 3 帧的 scan 数据逐点相同（或有效点集合相同）
         # 5 Hz 下 ≈ 0.6 s
```

**⚠ 审核点**：`SEN-004` 我**没有**加 `motion_expected` 前置条件。理由：真实激光在静止时仍有**噪声抖动**（测距噪声 ~mm 级），逐点完全相同的概率极低；能"逐点完全相同"基本可断定是数据冻结。
**但这依赖传感器特性**——如果仿真或某些雷达在静止时输出**确定性**的相同帧，此判据会误报。**需要你确认：你的激光在机器人静止、场景静止时，连续帧是否逐点相同？** 如果不相同，此判据可无条件使用；如果相同，必须加 `motion_expected`。

**`SEN-005` IMU 零方差**

```
前置条件:  motion_expected == true
异常      ⟺  var(imu.lin_acc) < σ²_min  ∨  var(imu.ang_vel) < σ²_min
            持续 T_stuck = 1.0 s
σ²_min  = 实测噪声底 / 10
```

**`LOC-007` 位姿冻结**

```
前置条件:  motion_expected == true          # ← 静止时位姿本就不变
异常      ⟺  (max(pose) − min(pose)) < 1e-9  超过 T_loc_frozen = 1.0 s
            且定位源仍在持续发布（区别于 LOC-005 超时）
```

**`SEN-006` 抑制规则**

```
当 motion_expected == false 时：
  抑制  SEN-003 / SEN-004 / SEN-005 / LOC-007
  改为检查"不应有的变化"（见 CMD-012）
```

**`SYS-010` 打滑**

```
异常  ⟺  |∫v_wheel dt − Δp_odom|  >  max(0.10 m, 0.3 × |Δp_odom|)   在 2 s 窗口内
      ∨  |a_imu − a_wheel|         >  阈值
```

### 2.3 语义类判据（数据"讲不讲得通"）

**`SEN-011` 数值域合法性 —— 最容易被低估的判据**

```
异常  ⟺  任一安全相关字段 ∈ {NaN, ±inf}（激光预期 inf 除外）
      ∨  超出物理量程：
            |v|                ≤ 1.0 m/s
            |ω|                ≤ 10 rad/s
            voltage            ∈ [0, 60] V
            battery.percentage ∈ [0, 1]
```

**为什么危险**：`NaN > x` 恒为 `false`。一条含 `NaN` 的速度指令会**静默通过所有上限检查**（因为比较都返回 false），然后进入控制器。这是"安全检查看起来通过了"的经典陷阱。同样，`inf` 会让 `min()` 计算失效。

**`SEN-007` / `LOC-003` 协方差**

```
异常(warn)      ⟺  cov > 0.05     # S2
异常(critical)  ⟺  cov > 0.25     # S3  (σ ≈ 0.5 m)

⚠ 哨兵值: 差速里程计对 z/roll/pitch 填 1e12，含义是"不可观测"，不是"极不确定"。
   必须只判定可观测自由度（x / y / yaw），否则每次正常行驶都误报。
```

**`SEN-008` 偏航交叉校验**

```
前置条件:  |ω| > 0.1 rad/s 的累计时间 > 1.0 s     # 无转动时偏航差值无意义
异常      ⟺  |Δψ_odom − Δψ_imu| > 10°            在 T_xcheck = 5.0 s 窗口内
```

**`SEN-009` 轮速交叉校验**

```
异常  ⟺  |odom.speed − (v_L + v_R)/2|  >  max(0.05 m/s, 0.25 × |v_cmd|)
```

**`SEN-010` 激光与运动一致性**

```
前置条件:  Δd > 0.20 m（机器人确实前进了）  ∧  ¬scan.no_return
异常      ⟺  Δd_obs > −0.5 × Δd     # 前进了但前方距离没按比例减小
```

**`COL-008` 距离突变**

```
前置条件:  该帧里程计位移 远小于  |Δd|
异常      ⟺  |front_range[k] − front_range[k−1]| > 0.50 m
```

**`LOC-001` / `LOC-002` 位姿跳变**

```
异常(LOC-001)  ⟺  Δp > 0.50 m   ∧   Δp/Δt > 2.0 m/s
异常(LOC-002)  ⟺  |Δψ| > 30°

判定合理性:  ω_max = 2.84 rad/s，10 Hz 下偏航单帧物理上界 ≈ 16° < 30°，故 30° 物理上不可能。
```

**`LOC-006` 定位—里程计偏差**

```
异常  ⟺  |Δp_loc − Δp_odom| > max(0.10 m, 0.3 × |Δp_odom|)   在 T_loc_xcheck = 2.0 s 内
```

**`LOC-009` 长期漂移**

```
异常  ⟺  任一或组合，在 T_drift = 10 s 窗口内：
          ① |Δp_loc − Δp_odom|            > 0.10 m
          ② 两个独立定位源持续偏离          > d_tol
          ③ 长期平均 |Δp_loc − Δp_odom| 单调增长
        超过 0.30 m → 升 S4
```

**`LOC-008` 置信度**

```
前置条件:  定位器提供置信度 / 匹配分数
异常      ⟺  confidence < conf_min  ∨  match_score < score_min
            持续 T_conf = 1.0 s
conf_min 取"正常导航时置信度分布的第 5 百分位"
```

**`COL-005` 停止距离充分性（核心判据）**

```
异常  ⟺  d_obs  <  S_stop(v_current)

S_stop(v) = v·T_detect + v·T_ctrl + v²/(2·a_brake) + C_safety + Z_sensor

v_current = max(|odom.speed|, |cmd.v|)     # 取大者，偏保守
```

代入基准值（`v = 0.22 m/s`）：

| 分量 | 值 |
|---|---|
| `v·T_detect`（0.05 s） | 0.011 m |
| `v·T_ctrl`（0.10 s） | 0.022 m |
| `v²/(2·a_brake)`（0.50 m/s²） | 0.048 m |
| `C_safety` | 0.050 m |
| `Z_sensor` | ≈0.002 m |
| **`S_stop`** | **≈ 0.133 m** |

**⚠ 仿真下的严重问题**：Gazebo 激光 5 Hz → `T_detect = 0.2 s` → `S_stop ≈ 0.30 m`，**是现有 `critical_range_m = 0.15 m` 的两倍**。判据成立时机器人已经撞上了。

**`COL-006` 动态限速带**

```
异常(限速)  ⟺  1.2 × S_stop  <  d_obs  <  2.0 × S_stop
```

**`COL-014` SSM（叠加人员接近速度）**

```
异常  ⟺  d_obs  <  v_robot·T_total + K_person·T_total + C_safety

K_person ≈ 1.6 m/s   # 人员步行接近速度
T_total = T_detect + T_ctrl + T_brake
```

**⚠ 审核点**：`COL-005` 假设障碍静止；一旦现场有人，**必须叠加 `K_person·T_total`**。这是很多 AMR 项目漏掉的一项——静态障碍的停止距离公式直接照搬到人身上，会得出偏小的保护区。**你的现场是否有人？**（决定 `COL-013`/`COL-014` 是强制还是可选）

**`SYS-009` 电机过流/堵转**

```
异常(过流)  ⟺  |I| > I_max            持续 300 ms
异常(堵转)  ⟺  |I| > 0.7 × I_max  ∧  |ω_wheel| < 0.01 rad/s  ∧  motion_expected
```

**`SYS-016` 参数完整性**

```
异常  ⟺  参数校验和失败  ∨  参数超出安全范围（如 v_max > 0.22）
```

**`SYS-001` 掉电**

```
异常  ⟺  V_supply < V_min_cutoff      # 按电池组标定，留 ≥ 500 ms 制动能量
```

### 2.4 跨源复合判据（9 条 —— 抓静默失效的关键）

| ID | 源 A | 源 B | 判据 | 需要的前置条件 |
|---|---|---|---|---|
| `SEN-008` | `odom.yaw` | `imu` 陀螺积分 | 偏航增量差 `> 10°/5 s` | 累计转动 > 1 s |
| `SEN-009` | `odom.speed` | `joint_states` | 速度差 `> max(0.05, 0.25·\|v_cmd\|)` | 都有数据 |
| `SEN-010` | `scan.front_range` | `odom` 位移 | 前进 `0.2 m` 但距离未减小 | `¬no_return` |
| `CMD-011` | `cmd` | `odom` | 指令—执行不一致 | `command.valid` |
| `MOT-012` | `motion_expected` | `odom.speed` | 该动没动 | `valid`（见 §7 决策 1） |
| `LOC-006` | `pose` | `odom` | 位移偏差 `> tol` | 都有数据 |
| `LOC-009` | `pose` | `odom` / 第二定位源 | 长期漂移 | 足够长的窗口 |

| `COL-008` | `scan` | `odom` 位移 | 距离突变而机器人未动 | 该帧有效 |

**设计原则**：跨源判据必须输出**三态**——`一致` / `不一致` / **`无法判定`**。
缺少任一源时，必须报"无法判定"，**不得**报"不一致"（现有 `command.valid`/`consistent` 已是此模式，需推广）。

**建议拆成两个量**：`motion_commanded`（有指令）与 `motion_observed`（实测在动）。请确认是否需要拆分。

|---|---|
| 文档编号 | RSS-001 |
| 版本 | v1.0 |
| 适用平台 | 差速轮式移动机器人 / AMR（基准平台：TurtleBot3 Burger + ROS 2 Humble + Gazebo 11） |

> **本文件的定位**：把"设计者意识到的风险"翻译成**可执行、可标定、可验证、可追溯**的安全规则。
> 每条规则都必须回答五个问题：**什么时候触发、阈值是多少、触发后做什么、怎么恢复、凭什么这么定**。
> 只写"要注意碰撞"不是规则，是愿望。规则必须是"当 `front_range < 1.2·S_stop` 持续 100 ms 时，速度上限降至 0.10 m/s"这种形式。

## 1. 目的与范围

### 1.1 目的

为差速轮式移动机器人定义一套完整的安全规则，使机器人能够在**任意单一故障**（single fault）下进入安全状态，并在**可预见的误用**下不产生不可接受的风险。

### 1.2 范围内（In Scope）

- 运动学限制与运动指令的合法性判定
- 碰撞风险与停止距离核算
- 传感器失效检测（超时 / 卡死 / 不合理）
- 指令与控制通道的安全
- 定位失效检测
- 通信中断与降级
- 系统自身完整性（掉电、进程崩溃、看门狗、驱动过载）

### 1.3 范围外（Out of Scope）

- 机械本安设计（锐边、夹点、负载固定）→ ISO 12100 风险降低的第一层
- 电气安全（接地、绝缘、电池热失控阻断）→ IEC 60204-1 / IEC 62133
- 功能安全软件的实现认证（本文件定义"要什么 PL"，不构成"已达成 PL d"的证明）
- 网络信息安全 / 防篡改 → 建议单独引用 IEC 62443

> **重要说明**：ISO 10218 系列面向工业机器人（尤其是固定式机械臂）。对 AMR，**产品级主标准是 ISO 3691-4**。本文件以 ISO 10218-1:2025 的功能安全方法论（安全功能表 + 默认 PL）为骨架，以 ISO 3691-4 的场景要求为血肉。两者关系见 [§13](#13-iso-13849-1-功能安全分配)。

## 2. 规范性引用与术语

### 2.1 引用文件

| 标准 | 用途 | 本文件引用点 |
|---|---|---|
| **ISO 10218-1:2025** | 工业机器人安全要求——功能安全、机器人分级、停机功能 | §13 默认 PL 来源 |
| **ISO 10218-2:2025** | 机器人应用与单元——安全功能清单 | §13.2 |
| **ISO 13849-1** | 控制系统安全相关部件——PL 与架构 | §13.1 |
| **ISO 12100** | 风险评估与风险降低方法论 | §5 |
| **ISO 3691-4** | 无人驾驶工业车辆——AMR 直接适用标准 | §7、§11 |
| **ISO 13855:2024** | 安全防护定位——基于接近速度的距离计算 | §7.2 |
| **IEC 61496** | 电敏保护设备（安全激光雷达） | §7.6 |
| **IEC 61508** | 功能安全基础标准 | §13.1 |

**ISO 10218-1:2025 的相对 2011 版关键变化**（直接决定本文件的 PL 分配写法）：

1. **废除"一刀切 PL d + Cat 3"**：改为按**安全功能逐条**给出默认性能等级（default PL）。设计者可偏离默认值，但必须用更全面的风险评估来论证，并承担更高文档成本。
2. **引入机器人分级**：**Class 1**（经合理判断不构成显著危险的极弱机器人，控制要求降低，通常 **PL b**）；**Class 2**（其余全部，适用较高要求）。
3. **新增 Normal Stop（正常停止）安全功能**：与急停分离，用于换班等常规停机，避免滥用急停。
4. **集成 ISO/TS 15066**：协作类型（HGC / SSM / PFL）与准静态/瞬态接触的力与压力限值并入 Part 2。
5. **新增/强化**：网络安全、启动联锁、重启联锁与复位、机械强度、提升作业。

> 本平台（TurtleBot3 级差速底盘）按 **Class 2** 处理：虽是小型轻载机器人，但其运动速度与质量足以对人员造成伤害（尤其夹伤、绊倒、撞伤），**不得**按 Class 1 降级。

### 2.2 术语与状态常量

沿用现有消息 `TopicHealth.msg` 的状态常量，**不另起一套**：

| 值 | 名称 | 含义 | 安全语义 |
|---|---|---|---|
| 0 | `UNKNOWN` | 从未收到样本 | **不等于安全**，按下限处理 |
| 1 | `OK` | 在超时内持续到达 | 正常 |
| 2 | `STALE` | 超时内无新样本 | 数据不可信 |
| 3 | `ERROR` | 有数据但不可用 | 数据不可信 |
| 4 | `CRITICAL` | 安全相关失效 | 必须进入安全状态 |

聚合规则沿用现有实现：**取最坏值**（worst-status-wins），`UNKNOWN` 在安全判定中视为 `STALE`。

## 3. 总体安全架构与状态机

### 3.1 三层架构

```
┌──────────────────────────────────────────────────────────────┐
│ 第 3 层：安全门控（safety_gate）—— 强制执行                    │
│   唯一的 /cmd_vel 出口仲裁器。规则未通过时物理截断或改写指令。  │
│   独立进程，独立看门狗；不依赖监控是否存活。                    │
├──────────────────────────────────────────────────────────────┤
│ 第 2 层：安全状态机（safety_state_machine）—— 决策              │
│   消费 /robot_safety/monitor/state，输出状态与速度包络。        │
├──────────────────────────────────────────────────────────────┤
│ 第 1 层：状态监控（robot_safety_monitor）—— 观测【已实现】      │
│   只观测、只告警，不做决策；不构成安全链路的单点。               │
└──────────────────────────────────────────────────────────────┘
```

**设计不变量（Invariant）**：

- **INV-1**：第 1 层故障**不得**导致机器人失去保护。监控挂掉必须由第 3 层的独立看门狗捕获（见 `SYS-016`）。
- **INV-2**：安全状态是**停止**。任何判定不确定时，默认方向都是减速停车，而非继续运动。
- **INV-3**：安全功能不依赖非安全通道（普通 Wi-Fi、非安全 DDS 主题）的可用性；远程链路只用于**附加**监控。
- **INV-4**：所有安全相关判定使用**墙钟时间**（沿用现有实现），不用消息时间戳，以防仿真暂停或回放造成"陈旧数据看起来新鲜"。

### 3.2 状态机定义

| 状态 | 含义 | 允许运动 | 速度包络 |
|---|---|---|---|
| `INIT` | 上电自检 | 禁止 | 0 |
| `NORMAL` | 全部安全条件满足 | 允许 | 额定限值 |
| `DEGRADED` | 非致命降级 | **限速允许** | 可配置包络（默认 50%） |
| `PROTECTIVE_STOP` | 保护性停止（可自动恢复） | 禁止 | 0（受控减速） |
| `SAFE_STOP` | 安全停止（需人工确认复位） | 禁止 | 0（受控减速） |
| `EMERGENCY_STOP` | 急停（硬件回路） | 禁止 | 0（断电制动） |
| `FAULT` | 不可恢复故障 | 禁止 | 0（需维修） |

**迁移规则**：

| 从 | 到 | 触发 |
|---|---|---|
| `INIT` | `NORMAL` | 全部自检通过 + 所有必需源 `OK` + 人工/遥控确认启动 |
| `NORMAL` | `DEGRADED` | 任一 WARN 级规则触发，且无 CRITICAL |
| `NORMAL`/`DEGRADED` | `PROTECTIVE_STOP` | 任一 CRITICAL 级规则触发（可自动恢复型） |
| `NORMAL`/`DEGRADED`/`PROTECTIVE_STOP` | `SAFE_STOP` | 持续性/需复位型故障（如 `SEN-003` 卡死、`LOC-001` 跳变） |
| 任意 | `EMERGENCY_STOP` | 硬件急停回路断开，或 `SYS-001` 掉电 |
| 任意 | `FAULT` | `SYS-*` 不可恢复故障 |
| `PROTECTIVE_STOP` | `DEGRADED`/`NORMAL` | 触发条件消失 + 持续 `T_recover` 无复发 + （按规则）远程/人工确认 |
| `SAFE_STOP`/`FAULT` | `INIT` | 人工复位（重启联锁，见 `SYS-018`） |

> **重启联锁**：从 `SAFE_STOP` / `EMERGENCY_STOP` / `FAULT` 复位**不得**自动恢复运动，必须经显式人工动作。这是 ISO 10218-1:2025 明确强化的要求。

| `SYS` | 系统完整性 System Integrity | 18 |
| **合计** | | **89** |

### 4.2 规则模板

每条规则固定 8 个字段：

| 字段 | 说明 |
|---|---|
| **ID / 名称** | 稳定标识符，代码与测试可直接引用 |
| **等级** | `S1`（提示）/ `S2`（告警 WARN）/ `S3`（保护停 CRITICAL）/ `S4`（安全停/急停） |
| **强制性** | 强制 / 条件 / 可选；条件规则须写明成立条件 |
| **触发条件** | 可判定的布尔表达式，含持续时间 |
| **阈值** | 具体数值 + 标定来源 + 是否需现场标定 |
| **响应** | 安全动作 + 目标状态 + 响应时限 |
| **恢复** | 解除条件 + 防抖时间 + 是否需人工复位 |
| **依据与验证** | 标准条款 + 验证方法（测试用例/标定方法） |

### 4.3 等级与响应映射

| 等级 | 目标状态 | 响应时限 | 典型动作 |
|---|---|---|---|
| `S1` | 不变 | 不适用 | 记录日志、UI 提示 |
| `S2` | `DEGRADED` | ≤ 200 ms | 降速至包络、告警、请求人工确认 |
| `S3` | `PROTECTIVE_STOP` | ≤ 200 ms | 受控减速至零、保持、可自动恢复 |
| `S4` | `SAFE_STOP` / `EMERGENCY_STOP` | ≤ 100 ms | 受控/断电停车、需人工复位 |

> **响应时限的依据**：本平台软件链路（ROS 2 回调 + 状态机 + 门控）实测总时延按 `T_ctrl = 100 ms` 预留，`S4` 允许更短是因为急停走硬件回路而非软件。**该值必须实测标定后写入**（见 §14.3）。

**结论**：你的 7 大类框架是正确的，但有 **4 个结构性缺口**必须补齐才能称为"完整"——

1. **停止距离的定量核算**（第 4 条风险只写了问句，没有公式）；
2. **急停回路与重启联锁**（最基础的安全功能，却在清单中缺席）；
3. **执行层完整性**（电机、驱动、电流、温度——"系统本身损坏"目前只有一句话）；
4. **恢复策略**（所有规则都写了怎么停，几乎没写怎么安全地恢复）。

## 6. 类别 1：运动安全（MOT）

> 目标：把运动学量约束在**平台额定能力**与**场景允许**之内，并阻止突变指令对机械与人员的冲击。
> 原则：**拒绝而非截断**（见 `CMD-002`）——静默截断会让上层以为指令已生效，产生"控制器认为在走、实际没走"的隐性不一致。

### 运动学限值（基准平台 TurtleBot3 Burger，**必须现场标定**）

| 量 | 符号 | 额定值 | 保护停阈值 | 安全停阈值 | 说明 |
|---|---|---|---|---|---|
| 线速度 | `v_max` | 0.22 m/s | 0.22 m/s | 0.30 m/s | 制造商额定；可降至场景允许值 |
| 角速度 | `ω_max` | 2.84 rad/s | 2.84 rad/s | 3.50 rad/s | 差速原地旋转 |
| 线加速度 | `a_max` | 0.50 m/s² | 0.80 m/s² | 1.20 m/s² | 受地面附着限制 |
| 角加速度 | `α_max` | 3.00 rad/s² | 5.00 rad/s² | 8.00 rad/s² | — |
| 线加加速度 | `j_max` | 5.00 m/s³ | — | — | 抑制冲击 |
| 合成速度 | `v_cmd` | 见 `MOT-004` | — | — | 线+角耦合约束 |

---

**`MOT-001` 线速度上限**

- **等级**：`S2` / **强制**
- **触发**：`|v_cmd_linear| > v_max`
- **阈值**：`v_max = 0.22 m/s`（额定）；场景允许值 `v_scene ≤ v_max`，由风险评估指定
- **响应**：拒绝该指令 + `MOT_LIN_VEL_EXCEED`（S2）→ `DEGRADED`；**持续 > 500 ms 或连续 5 帧超限** → 升级 `S3` 保护停（判定为控制器失控而非偶发噪声）
- **恢复**：指令回到限值内且持续 `T_recover = 300 ms`；超限升级为 `S3` 后需确认
- **依据**：ISO 10218-1:2025（降速功能，默认 PL d）；ISO 3691-4（速度限制）
- **验证**：单元测试注入 `v=0.23`，断言拒绝且不发出运动指令；标定测试实测底盘在 `v_max` 下的机械稳定性

**`MOT-002` 角速度上限**

- **等级**：`S2` / **强制**
- **触发**：`|ω_cmd| > ω_max`
- **阈值**：`ω_max = 2.84 rad/s`
- **响应**：同 `MOT-001`，告警码 `MOT_ANG_VEL_EXCEED`
- **恢复**：同 `MOT-001`
- **依据**：同上
- **验证**：注入 `ω=3.0`，断言拒绝

**`MOT-003` 线加速度限制**

- **等级**：`S2` / **强制**
- **触发**：`|(v_cmd[k] − v_cmd[k−1]) / Δt| > a_max`
- **阈值**：`a_max = 0.50 m/s²`，`Δt` 取实际指令间隔（下限 20 ms，防止除零/尖峰）
- **响应**：拒绝 + `MOT_LIN_ACCEL_EXCEED`（S2）→ `DEGRADED`
- **恢复**：加速度回到限值内持续 300 ms
- **依据**：ISO 12100（冲击/甩出风险）；ISO 3691-4（平稳起停）
- **验证**：构造阶跃 0→0.22 m/s 单帧指令，断言被拒

**`MOT-004` 线/角速度合成约束（差速底盘耦合）**

- **等级**：`S2` / **强制**
- **触发**：指令落在底盘可达速度空间之外
- **阈值**：差速约束 `|v| + (W/2)·|ω| ≤ v_wheel_max`，其中 `W` 为轮距（TurtleBot3 Burger `W ≈ 0.160 m`，**待实测确认**），`v_wheel_max` 为单轮最大线速度（`≈ ω_wheel_max · r_wheel`，`r_wheel ≈ 0.033 m`）
- **响应**：拒绝 + `MOT_TWIST_INFEASIBLE`（S2）→ `DEGRADED`
- **恢复**：指令回到可达空间内持续 300 ms
- **依据**：平台运动学可达性；避免控制器积分饱和产生"指令已下、底盘未动"的假象（与 `CMD-011` 联动）
- **验证**：注入 `v=0.22, ω=2.84`（组合不可达），断言拒绝

**`MOT-005` 加加速度（jerk）限制**

- **等级**：`S1` / **条件**（成立条件：载有易倾覆/易碎负载，或现场有人）
- **触发**：`|Δa / Δt| > j_max`
- **阈值**：`j_max = 5.0 m/s³`
- **响应**：仅告警 + `MOT_JERK_HIGH`（S1），记录日志
- **恢复**：不适用
- **依据**：负载稳定性与乘坐舒适性；人机共存时降低碰伤风险
- **验证**：日志断言

**`MOT-006` 运动包络随状态收缩**

- **等级**：`S2` / **强制**
- **触发**：状态为 `DEGRADED`
- **阈值**：`v_env = 0.5 · v_scene`，`ω_env = 0.5 · ω_scene`（默认 50%，可配置）
- **响应**：速度上限整体收缩至包络 + `MOT_ENVELOPE_REDUCED`（S2）
- **恢复**：回到 `NORMAL` 后立即恢复原包络
- **依据**：ISO 10218-1:2025 降速安全功能；降级运行时降低风险暴露
- **验证**：进入 `DEGRADED` 后注入原额定速度指令，断言被压缩至包络内

**`MOT-007` 停车距离自动限速（与 COL 联动）**

- **等级**：`S3` / **强制**
- **触发**：见 `COL-005` 的核算结果——可用停止距离不足
- **阈值**：动态，见 §7.2
- **响应**：速度上限降至 `v_allow = max(0, (d_obs − C_safety − D_detect) / T_total)`（见 §7.2 公式反解），或直接保护停
- **恢复**：`d_obs` 恢复到 `≥ 1.5·S_stop` 持续 300 ms
- **依据**：ISO 13855:2024；ISO 3691-4
- **验证**：场景测试——以最大速度冲向障碍，断言在 `d_min` 前停车

**`MOT-008` 零速指令即停止**

- **等级**：`S2` / **强制**
- **触发**：`stop_command` 置位（`|v| ≤ deadband_lin` 且 `|ω| ≤ deadband_ang`）
- **阈值**：`deadband_lin = 0.02 m/s`，`deadband_ang = 0.10 rad/s`（沿用现有配置）
- **响应**：门控输出零速 + `MOT_STOP_REQUESTED`（S2）；断言 `|odom.speed| < 0.01 m/s` 于 500 ms 内达到
- **恢复**：收到非零有效指令
- **依据**：停机功能；防止"发了零速但底盘仍在动"（与 `CMD-012` 联动）
- **验证**：发零速后读里程计，断言速度收敛

**`MOT-009` 运动仅在武装状态下允许**

- **等级**：`S4` / **强制**
- **触发**：`armed == false` 时出现非零运动指令持续 `T_debounce = 100 ms`（去抖，容忍单帧噪声）
- **阈值**：非零判据同 `MOT-008`
- **响应**：**立即物理截断为零速**（不等去抖窗口）+ `MOT_UNARMED_COMMAND`（`S4`）→ `SAFE_STOP`（需人工复位；未武装状态下的运动指令意味着控制权或启动联锁已失效）
- **恢复**：显式武装（人工/受控流程）
- **依据**：ISO 10218-1:2025 启动联锁（start interlock）
- **验证**：未武装状态下发布 `v=0.1`，断言底盘不动

**`MOT-010` 倾角导致的运动禁止**

- **等级**：`S4` / **强制**
- **触发**：`tilt_deg > tilt_critical_deg`（`S4`）或 `> tilt_warn_deg`（`S2`）
- **阈值**：`tilt_warn_deg = 15°`，`tilt_critical_deg = 45°`（沿用现有配置；15° 提示爬坡/倾斜，45° 基本确定已翻倒）
- **响应**：`S2` → 降速 `DEGRADED`；`S4` → `SAFE_STOP` + `TILT_CRITICAL`（需人工扶正并复位）
- **恢复**：倾角回到 15° 以内持续 1.0 s + 人工复位
- **依据**：稳定性/翻倒风险
- **验证**：已在现有实现中（`TILT_HIGH`/`TILT_CRITICAL`）；补充恢复路径测试

**`MOT-011` 原地旋转的空间许可**

- **等级**：`S2` / **条件**（成立条件：机器人几何包络大于安全侧向距离）
- **触发**：`|ω_cmd| > 0.5 rad/s` 且任一方向最小距离 `< R_robot + C_safety`
- **阈值**：`R_robot` = 机器人外接圆半径（TurtleBot3 Burger `≈ 0.105 m`，**待实测**），`C_safety = 0.05 m`
- **响应**：限制 `ω` 至 `ω_safe = (d_min − R_robot − C_safety) / T_total`，或若 `d_min < R_robot + C_safety` 则保护停 + `MOT_ROTATION_BLOCKED`
- **恢复**：距离恢复
- **依据**：旋转扫掠面积远大于直行，是常被忽略的碰撞路径
- **验证**：贴近墙壁注入原地旋转指令，断言被限制/拒绝

**`MOT-012` 运动意图与实际运动的一致性（意图侧）**

- **等级**：`S2` / **强制**
- **触发**：`motion_expected == true` 且 `|odom.speed| < command.motion_threshold` 持续 `T_mismatch`
- **阈值**：`motion_threshold = 0.01`（沿用），`T_mismatch = 1.0 s`（可配置；需大于底盘起转时间）
- **响应**：`COMMAND_MISMATCH`（S2）→ `DEGRADED`；持续 3 s → `S3` 保护停（可能堵转/断轴，联动 `SYS-009`）
- **恢复**：实际运动恢复一致持续 1.0 s
- **依据**：ISO 13849-1（诊断覆盖率）；闭环完整性
- **验证**：已在实现中；补充升级路径测试

## 7. 类别 2：碰撞与距离安全（COL）

> 这是你清单里**最需要"变成公式"**的一类。你写的是"能不能在碰到障碍物之前停下来"——下面给出可核算的判据。

### 7.1 分层几何定义

```
              ┌─────── 前向扇区 (front_sector_half_angle) ───────┐
              │                                                  │
   机器人                d_obs = scan.front_range
   ╔══════╗  ← R_robot →  ←──────── 自由空间 ────────→  ▓▓ 障碍
   ║  ██  ║─────────────────────────────────────────────▓▓▓▓▓
   ╚══════╝
   外接圆半径 R_robot
```

| 符号 | 含义 | 取值 |
|---|---|---|
| `R_robot` | 机器人外接圆半径 | `≈ 0.105 m`（待实测） |
| `d_obs` | 前向扇区最小有效回波距离 | `scan.front_range` |
| `d_clear` | 需保证的最小自由距离 | 见 §7.2 |
| `θ_front` | 前向扇区半角 | `0.35 rad ≈ 20°`（沿用配置） |

### 7.2 停止距离核算（核心公式）

采用 ISO 13855:2024 的结构 `S = K·T + D_DS + Z`，针对移动机器人展开为各时延分量之和：

```
S_stop = D_detect + D_ctrl + D_brake + C_safety + Z_sensor

其中：
  D_detect = v · T_detect   检测时延×速度（激光采样 + 处理）
  D_ctrl   = v · T_ctrl     控制/通信时延×速度（ROS 链路 + 门控）
  D_brake  = v² / (2·a_brake)  制动距离（a_brake 实测减速度）
  C_safety = 0.05 m         固定安全余量（标定不确定度）
  Z_sensor = d_obs · tan(θ_err)  传感器角度误差导致的横向裕量
```

**时延与减速度取值（必须实测标定）**：

| 参数 | 符号 | 基准值 | 标定方法 |
|---|---|---|---|
| 检测时延 | `T_detect` | 0.05 s | 激光采样周期 + 算法耗时（5 Hz → 单周期即 0.2 s，**仿真中须按 0.2 s 取值**） |
| 控制时延 | `T_ctrl` | 0.10 s | 注入阶跃，测指令到轮速变化的时间 |
| 制动减速度 | `a_brake` | 0.50 m/s² | 满速急停，测制动距离反解 |
| 传感器角度误差 | `θ_err` | 0.5° | 激光数据手册 / 实测 |

**代入基准值（`v = 0.22 m/s`，`T_detect = 0.05 s`，`T_ctrl = 0.10 s`，`a_brake = 0.50 m/s²`）**：

```
D_detect = 0.22 × 0.05 = 0.011 m
D_ctrl   = 0.22 × 0.10 = 0.022 m
D_brake  = 0.22² / (2×0.5) = 0.048 m
C_safety = 0.050 m
Z_sensor ≈ 0.22 × tan(0.5°) ≈ 0.002 m
────────────────────────────────────
S_stop ≈ 0.133 m   （在 v = 0.22 m/s 下）
```

> **仿真下的警告**：Gazebo TurtleBot3 的激光仅 **5 Hz**，`T_detect` 实为 **0.2 s**，此时 `S_stop ≈ 0.30 m`——**超过现有 `obstacle.critical_range_m = 0.15 m` 一倍**。这意味着**当前配置在仿真中根本停不住**。这是必须修正的定量缺陷，见 §15。

**判据**：要求 `d_obs ≥ S_stop(v)`，等价于速度上限：

```
v_allow(d_obs) = ( −b + √(b² + 4·(d_obs − C_safety)/(2·a_brake)) )  ... 数值反解即可
```

### 7.3 三级距离阈值

| 级别 | 判据 | 等级 | 目标状态 |
|---|---|---|---|
| 提示 | `d_obs < 2.0 · S_stop` | `S1` | 不变 |
| 降速 | `d_obs < 1.5 · S_stop` | `S2` | `DEGRADED` + 限速 |
| 保护停 | `d_obs < 1.2 · S_stop` | `S3` | `PROTECTIVE_STOP` |
| 安全停 | `d_obs < 1.0 · S_stop` | `S4` | `SAFE_STOP` |

---

**`COL-001` 障碍接近告警**

- **等级**：`S2` / **强制**
- **触发**：`front_range < obstacle.warn_range_m` 持续 `T_debounce = 100 ms`
- **阈值**：`warn_range_m = 0.30 m`（现有默认）；**且必须满足 `warn_range_m ≥ 1.5·S_stop`**
- **响应**：`OBSTACLE_NEAR`（S2）→ `DEGRADED` + 限速
- **恢复**：`front_range > warn_range_m × 1.2`（迟滞 20%）持续 300 ms
- **依据**：ISO 3691-4（人员/障碍检测与降速）
- **验证**：已在实现中；补充迟滞与去抖测试

**`COL-002` 障碍紧急停止**

- **等级**：`S3` / **强制**
- **触发**：`front_range < obstacle.critical_range_m`
- **阈值**：`critical_range_m = 0.15 m`（现有默认）；**必须修正为 `≥ 1.2·S_stop`**——按仿真参数应为 `≈ 0.36 m`，按真实 10 Hz 激光可降至 `≈ 0.16 m`
- **响应**：`OBSTACLE_CRITICAL`（S3）→ `PROTECTIVE_STOP`
- **恢复**：`front_range > critical_range_m × 1.5` 持续 1.0 s + 确认
- **依据**：ISO 13855:2024；ISO 3691-4
- **验证**：见 `COL-005` 场景测试

**`COL-003` 全向最小距离监测**

- **等级**：`S2` / **强制**
- **触发**：`closest_range < R_robot + C_safety`（任意方向）
- **阈值**：`R_robot + C_safety ≈ 0.155 m`
- **响应**：`OBSTACLE_NEAR`（S2）→ 禁止朝该方向运动 + `DEGRADED`
- **恢复**：距离恢复 + 迟滞
- **依据**：接触风险；防止侧向刮擦
- **验证**：左侧贴墙注入左转指令，断言被拒

**`COL-004` 无回波的正确解释**

- **等级**：`S1` / **强制**（语义规则，非新告警）
- **触发**：`scan.no_return == true` 且 `scan` 源状态为 `OK`
- **阈值**：不适用
- **响应**：**不得**判定为传感器故障，视为"前方空阔"；**但**若 `no_return` 且源为 `STALE`/`ERROR`，则按 `SEN-001` 处理为"未知"
- **恢复**：不适用
- **依据**：Gazebo 射线传感器对超量程返回 `inf`；`inf` 是正常信号
- **验证**：现有实现已正确处理（`no_return` 字段）；补充回归测试

**`COL-005` 停止距离充分性（核心规则）**

- **等级**：`S3` / **强制**
- **触发**：`d_obs < S_stop(v_current)`，其中 `S_stop` 按 §7.2 实时计算
- **阈值**：动态；`v_current` 取 `max(|odom.speed|, |cmd.v|)`（取大者，偏保守）
- **响应**：立即 `PROTECTIVE_STOP` + `COL_INSUFFICIENT_STOPPING_DISTANCE`；响应时限 ≤ `T_ctrl`
- **恢复**：`d_obs ≥ 1.5·S_stop(v_scene)` 持续 1.0 s
- **依据**：**ISO 13855:2024 —— 这是"能否在碰到前停下"的唯一正当判据**
- **验证**：**关键场景测试**——满速直冲障碍物，记录最小停止距离 `d_stop_measured`，断言 `d_stop_measured ≤ S_stop_predicted`；若不成立则修正 `a_brake`/`T_ctrl`

**`COL-006` 动态限速（距离自适应）**

- **等级**：`S2` / **强制**
- **触发**：`1.2·S_stop < d_obs < 2.0·S_stop`
- **阈值**：`v_allow = v_allow(d_obs)` 按 §7.2 反解，且 `v_allow ≤ v_scene`
- **响应**：门控将速度压至 `v_allow` + `COL_SPEED_LIMITED_BY_RANGE`（S2）→ `DEGRADED`
- **恢复**：`d_obs > 2.0·S_stop` 持续 300 ms 后逐步恢复（**限加速度**，避免突加速）
- **依据**：ISO 13855:2024；ISO 10218-1:2025 降速功能（PL d）
- **验证**：渐进接近障碍，断言速度随距离单调下降

**`COL-007` 传感器时延导致的额外裕量**

- **等级**：`S2` / **条件**（成立条件：`T_detect > 0.1 s`，即低采样率传感器）
- **触发**：`S_stop` 计算中 `T_detect` 超过标称值
- **阈值**：`T_detect` 取**实测采样周期的 1.5 倍**（覆盖最坏采样相位）
- **响应**：自动扩大 `S_stop` 并收紧限速 + `COL_LATENCY_MARGIN_APPLIED`（S2）
- **恢复**：采样率恢复
- **依据**：低采样率下最坏情况延迟 = 一整个采样周期
- **验证**：将激光降至 5 Hz，断言限速收紧

**`COL-008` 障碍距离突变（Teleport）检测**

- **等级**：`S3` / **强制**
- **触发**：相邻两帧 `front_range` 变化 `|Δd| > Δd_max` 且**里程计显示机器人未产生相应位移**
- **阈值**：`Δd_max = 0.50 m` 每帧（对应最大合理相对运动）
- **响应**：`COL_RANGE_TELEPORT`（S3）→ 保护停（优先怀疑传感器故障，联动 `SEN-011`）
- **恢复**：检测正常持续 1.0 s + 确认
- **依据**：物理不可能事件 = 传感器或数据链路故障
- **验证**：注入单帧突变数据，断言保护停

**`COL-009` 速度指令与距离裕量的联合门控**

- **等级**：`S3` / **强制**
- **触发**：门控入口处的**最终**检查（对已仲裁指令再做一次距离核算）
- **阈值**：同 `COL-005`
- **响应**：拒绝放行 + `COL_GATE_BLOCKED`（S3）
- **恢复**：条件满足
- **依据**：安全门控必须是独立的最后防线（INV-1）；上层状态机被绕过时仍能保护
- **验证**：绕过状态机直接向门控注入指令，断言仍被拦截

**`COL-010` 传感器覆盖与运动方向匹配**

- **等级**：`S2` / **强制**
- **触发**：指令速度方向落在传感器有效视场之外（如激光视野 < 360° 而指令含侧向/后向分量）
- **阈值**：有效视场由 `scan.angle_min/angle_max` 与 `valid_point_count/point_count` 推断；要求覆盖方向上的有效点比例 `> 0.5`
- **响应**：禁止该方向运动 + `COL_BLIND_DIRECTION`（S2）→ `DEGRADED`
- **恢复**：方向回到覆盖范围内
- **依据**：**盲区运动 = 不可检测的碰撞风险**；这是"距离安全"的隐含前提
- **验证**：模拟后向运动（激光仅前向 180°），断言被拒

**`COL-011` 有效回波比例过低**

- **等级**：`S2` / **强制**
- **触发**：`valid_point_count / point_count < r_valid_min`
- **阈值**：`r_valid_min = 0.30`（低于此值无法信任最小距离）
- **响应**：`COL_LOW_VALID_RETURNS`（S2）→ `DEGRADED` + 限速；持续 2 s → `S3` 保护停
- **恢复**：比例恢复 > 0.5 持续 1.0 s
- **依据**：玻璃/镜面/吸光表面导致回波丢失，此时"最近障碍距离"不可信
- **验证**：注入 80% `inf` 的扫描，断言降级

**`COL-012` 停车后残余速度确认**

- **等级**：`S3` / **强制**
- **触发**：进入 `PROTECTIVE_STOP`/`SAFE_STOP` 后 `T_stop_confirm = 500 ms` 内 `|odom.speed| > 0.02 m/s`
- **阈值**：`T_stop_confirm = 500 ms`，残余速度阈值 `0.02 m/s`
- **响应**：`COL_RESIDUAL_MOTION`（S3）→ 升级 `SAFE_STOP`；若仍不停 → 触发硬件急停
- **恢复**：需人工复位
- **依据**：**"发出了停机指令" ≠ "已经停下"**；必须闭环确认
- **验证**：模拟刹车失效（强制 odom 保持速度），断言升级至急停

**`COL-013` 人员检测（人机共存）**

- **等级**：`S4` / **条件**（成立条件：现场存在人员，或风险评估判定需要 —— 见 ISO 3691-4）
- **触发**：安全激光雷达/视觉检测到人员进入保护区域
- **阈值**：保护区域 = `S_stop(v) + D_person`，其中 `D_person` 为人员接近距离（按 ISO 13855 的接近速度分量，人员步行 `K ≈ 1.6 m/s`）
- **响应**：`PROTECTIVE_STOP` 或按 SSM 降速 + `COL_PERSON_DETECTED`；**要求 PL d / Cat 3，且传感器满足 IEC 61496（安全激光雷达）**
- **恢复**：人员离开保护区 + 人工确认（依据现场策略）
- **依据**：ISO 3691-4；ISO 10218-1:2025 速度与分离监控（SSM）；ISO 13855:2024
- **验证**：人员进入测试（必须使用安全级传感器，非普通激光雷达）

**`COL-014` 速度与分离监控（SSM）**

- **等级**：`S4` / **条件**（同 `COL-013`）
- **触发**：`d_obs` 与相对接近速度使得"制动停止所需距离"逼近可用距离
- **阈值**：`T_stop_total = T_detect + T_ctrl + T_brake`；要求 `d_obs ≥ v · T_stop_total + C_safety`，且人员接近速度为**叠加项**：`d_min = v_robot·T_total + K_person·T_total + C`
- **响应**：连续降速（而非二元停）以维持最小分离距离 + `COL_SSM_LIMITING`
- **恢复**：分离距离恢复
- **依据**：ISO 10218-1:2025 / ISO 10218-2:2025 SSM 协作类型；默认 **PL d**
- **验证**：AGV 与人员相向运动场景

> **`COL-014` 的公式与 `COL-005` 的差别**：`COL-005` 假设障碍静止；一旦现场有人，必须叠加人的接近速度 `K_person·T_total`。这正是 ISO 13855 的 `K·T` 项，也是很多 AMR 项目漏掉的一项。

## 8. 类别 3：传感器安全（SEN）

> 你的清单里"Sensor timeout"写了两遍（重复项，已合并），并列出 stuck / plausibility。这三者的**判据完全不同**，必须分开定义：
>
> - **Timeout**：时间维度——"数据来没来"
> - **Stuck**：变化维度——"数据变没变"（即使一直在来）
> - **Plausibility**：语义维度——"数据的值讲不讲得通"
>
> **关键洞察**：**Stuck 检测必须先判断运动状态**。机器人静止时，激光读数本来就不变——此时判定"卡死"是典型的误报来源。

---

**`SEN-001` 传感器数据超时（Timeout）**

- **等级**：`S3` / **强制**
- **触发**：`now_wall − last_wall_time > timeout_sec`
- **阈值**（沿用现有配置，但建议按实际频率收紧）：

| 源 | 现有超时 | 实测频率（仿真） | 建议超时（真实硬件） |
|---|---|---|---|
| `/odom` | 1.0 s | ~30 Hz | `3 / f` ≈ 0.1 s |
| `/scan` | 1.0 s | **5 Hz** | `3 / f`，5 Hz 时 ≈ 0.6 s |
| `/imu` | 1.0 s | ~100 Hz | ≈ 0.05 s |
| `/joint_states` | 2.0 s | ~30 Hz | ≈ 0.2 s |
| `/cmd_vel` | 1.0 s | 指令频率 | 见 `CMD-007` |
| `/battery` | 5.0 s | 可选 | ≈ 1.0 s |

  通用公式：`timeout = max(3 · T_period, T_min)`；`T_min = 0.05 s`（防过紧误报）
- **响应**：`*_STALE`（现有告警码）→ `S3` 保护停（对安全相关源）；`UNKNOWN`（从未收到）按 `CRITICAL` 处理，**不得**当作 `OK`
- **恢复**：数据恢复到达 + 连续 `3 · T_period` 稳定 + 确认
- **依据**：ISO 13849-1（诊断）；**用墙钟，不用消息时间戳**（INV-4）
- **验证**：已在实现中（`*_STALE`/`*_MISSING`）；补充"按实际频率重算超时"的配置校验测试

**`SEN-002` 超时分级与升级**

- **等级**：`S2`→`S3` / **强制**
- **触发**：超时长度超过 `2 × timeout_sec`
- **阈值**：`2 × timeout_sec`
- **响应**：`S2` 阶段先降速 `DEGRADED`（给自己留反应余量）；超过 `2×` 升级 `S3` 保护停
- **恢复**：同 `SEN-001`
- **依据**：分级降级（graceful degradation）优于瞬时急停
- **验证**：注入延迟递增的数据流，断言状态升级序列

**`SEN-003` 传感器数值卡死（Stuck Value）**

- **等级**：`S4` / **强制**
- **触发**：**仅当 `motion_expected == true`** 时，某连续源在窗口内**数值完全不变**：
  `max(x) − min(x) < ε_stuck` 在 `T_stuck` 窗口内
- **阈值**：`T_stuck = 1.0 s`，`ε_stuck` 按源设定：

| 源 | `ε_stuck` | 说明 |
|---|---|---|
| `odom.speed` | `1e-6 m/s` | 运动中速度应有微小变化 |
| `odom.yaw` | `1e-6 rad` | 运动中偏航必变 |
| `imu.ang_vel_z` | `1e-6 rad/s` | 静止时也可能极小，故要求运动 |
| `scan.ranges` | 见 `SEN-004` | 需按整帧比较 |
| `joints.max_abs_velocity` | `1e-6` | 运动中轮速必变 |

- **响应**：`SEN_STUCK`（`S4`）→ `SAFE_STOP`（卡死通常意味着传感器或驱动固件冻结，需人工介入）
- **恢复**：数值恢复变化 + 人工复位
- **依据**：ISO 13849-1（诊断覆盖率 DC）；冻结传感器比丢失传感器更危险——它**持续提供看似合理的错误数据**
- **验证**：冻结某源的值并令机器人运动，断言触发

**`SEN-004` 激光整帧冻结检测**

- **等级**：`S4` / **强制**
- **触发**：连续 `N_frozen` 帧的扫描数据**逐点相同**（或有效点集合完全相同）
- **阈值**：`N_frozen = 3` 帧（5 Hz 下 = 0.6 s）
- **响应**：`SCAN_FROZEN`（`S4`）→ `SAFE_STOP`
- **恢复**：帧间出现差异 + 人工复位
- **依据**：驱动/发布器冻结；与"无回波"（`COL-004`）明确区分
- **验证**：replay 同一帧 3 次，断言触发；另测"真实静止场景下激光仍在噪声抖动"不触发

**`SEN-005` IMU 零方差检测**

- **等级**：`S3` / **强制**
- **触发**：`var(imu.lin_acc) < σ²_min` 或 `var(imu.ang_vel) < σ²_min` 持续 `T_stuck`，**且** `motion_expected == true`
- **阈值**：`σ²_min` 取传感器噪声底实测值的 1/10；`T_stuck = 1.0 s`
- **响应**：`IMU_FROZEN`（S3）→ `PROTECTIVE_STOP`
- **恢复**：方差恢复 + 确认
- **依据**：真实 IMU 一定有噪声；零方差 = 数值被固定
- **验证**：注入恒定 IMU 流，断言触发

**`SEN-006` 传感器卡死的运动状态门控（防误报规则）**

- **等级**：`S1` / **强制**（抑制规则）
- **触发**：`motion_expected == false`（机器人应静止）
- **响应**：**抑制** `SEN-003`/`SEN-004`/`SEN-005` 的判定；改为检查"静止期间是否出现不应有的变化"（异常运动，见 `CMD-012`）
- **依据**：静止机器人的传感器读数本应不变；不门控会产生大量误报，导致告警疲劳（alarm fatigue），最终使操作员忽略真实告警
- **验证**：机器人静止 60 s，断言不产生 stuck 告警

**`SEN-007` 里程计协方差不合理**

- **等级**：`S2` / **强制**
- **触发**：可观测自由度（x/y/yaw）的方差 `> odom.pose_cov_warn`（`S2`）或 `> 10× warn`（`S3`）
- **阈值**：`pose_cov_warn = 0.05`，`twist_cov_warn = 0.05`（沿用现有）
- **响应**：`POSE_UNCERTAIN` / `TWIST_UNCERTAIN`（S2）→ `DEGRADED` + 限速；严重超限 → `S3`
- **恢复**：协方差恢复 + 迟滞
- **依据**：ISO 13849-1（数据有效性诊断）
- **验证**：**已实现**，含哨兵值 `1e12` 的正确处理（`z`/`roll`/`pitch` 表示"不可观测"而非"极不确定"）——这是已踩过的坑，必须保留测试

**`SEN-008` 里程计与 IMU 的交叉校验**

- **等级**：`S2` / **强制**
- **触发**：窗口 `T_xcheck = 5.0 s` 内，里程计偏航增量与 IMU 陀螺积分偏航之差 `|Δψ_odom − Δψ_imu| > ψ_tol`
- **阈值**：`ψ_tol = 10°`（5 s 窗口）；**仅在机器人有转动时判定**（`|ω| > 0.1 rad/s` 累计 > 1 s）
- **响应**：`SEN_CROSSCHECK_YAW`（S2）→ `DEGRADED` + 限速；持续 → `S3`
- **恢复**：偏差回到容差内持续 2.0 s
- **依据**：轮滑/打滑或 IMU 偏置会导致里程计与惯性解算发散——单看任一源都正常，**只有交叉校验能发现**
- **验证**：注入轮滑（odom 偏航 ×0.8），断言 5 s 内触发

**`SEN-009` 里程计与轮速的交叉校验**

- **等级**：`S2` / **强制**
- **触发**：`|odom.speed − v_wheel_derived| > v_tol`，其中 `v_wheel_derived = (v_L + v_R)/2` 由 `joint_states` 推出
- **阈值**：`v_tol = max(0.05 m/s, 0.25·|v_cmd|)`
- **响应**：`SEN_CROSSCHECK_WHEEL`（S2）→ `DEGRADED`；持续 2 s → `S3`（联动 `SYS-010` 打滑）
- **恢复**：一致持续 1.0 s
- **依据**：轮径误差、编码器故障、打滑
- **验证**：注入 joint_states 与 odom 不一致

**`SEN-010` 激光与运动的一致性**

- **等级**：`S2` / **强制**
- **触发**：机器人前进 `Δd > 0.20 m` 期间，前方扇区最小距离**未按预期减小**（`Δd_obs > −0.5·Δd`），且无 `no_return`
- **阈值**：位移阈值 `0.20 m`；一致性系数 `0.5`
- **响应**：`SEN_SCAN_MOTION_INCONSISTENT`（S2）→ `DEGRADED` + 限速；持续 → `S3`
- **恢复**：一致性恢复
- **依据**：激光朝向偏移、标定错误、数据错位
- **验证**：注入静止激光流而机器人前进，断言触发

**`SEN-011` 数值域合法性**

- **等级**：`S3` / **强制**
- **触发**：任意安全相关字段出现 `NaN` / `±inf`（除激光的预期 `inf` 量程外）/ 超出物理量程
- **阈值**：按字段定义（如 `|v| ≤ 1.0 m/s`、`|ω| ≤ 10 rad/s`、`voltage ∈ [0, 60] V`、`battery.percentage ∈ [0,1]`）
- **响应**：`SEN_VALUE_INVALID`（S3）→ 保护停；**整帧含 NaN 时丢弃该帧并计数**，连续 3 帧 → `SAFE_STOP`
- **恢复**：数据合法 + 确认
- **依据**：NaN 会静默污染后续所有比较（`NaN > x` 恒为 `false`），是"看起来安全检查通过"的经典陷阱
- **验证**：注入 NaN，断言被检出且不进入 `OK`

**`SEN-012` 时间戳与时钟合理性**

- **等级**：`S2` / **强制**
- **触发**：`stamp` 回退/跳跃 `> T_clock_jump = 1.0 s`；或 `wall_time` 与系统时钟偏差 `> 1.0 s`；或消息时间戳领先墙钟 `> 0.5 s`
- **阈值**：`T_clock_jump = 1.0 s`
- **响应**：`SEN_CLOCK_ANOMALY`（S2）→ 告警 + 使用墙钟继续判定（**不得**因时钟异常而停止超时判定）
- **恢复**：时钟稳定
- **依据**：INV-4；时钟跳变会破坏所有窗口计算
- **验证**：注入回退时间戳，断言超时判定仍基于墙钟

**`SEN-013` 采样率异常**

- **等级**：`S2` / **强制**
- **触发**：`measured_rate_hz < 0.5 × nominal_rate` 或 `> 2 × nominal_rate` 持续 2.0 s
- **阈值**：`nominal_rate` 由配置声明（现有 `rate_window_sec = 5.0` 已提供速率估计）
- **响应**：`SEN_RATE_ANOMALY`（S2）→ `DEGRADED`；若速率下降则自动扩大 `T_detect` 并收紧限速（联动 `COL-007`）
- **恢复**：速率恢复持续 2.0 s
- **依据**：降频直接放大停止距离
- **验证**：降频至 1/4，断言限速收紧

**`SEN-014` 电池与电源合理性**

- **等级**：`S2`/`S3` / **条件**（成立条件：`battery.monitor = true`，即平台有电量话题）
- **触发**：`percentage < warn_fraction`（S2）或 `< critical_fraction`（S3）；温度越限；电压突变
- **阈值**：`warn_fraction = 0.30`，`critical_fraction = 0.15`（沿用现有）；温度 `> 60 °C` 告警
- **响应**：`BATTERY_LOW`（S2）→ `DEGRADED` + 限速并请求返回充电；`BATTERY_CRITICAL`（S3）→ `PROTECTIVE_STOP`；温度越限 → 立即 `SAFE_STOP`（热失控前兆）
- **恢复**：充电或电量恢复 + 确认
- **依据**：掉电将绕过所有软件安全功能（INV：软件保护依赖供电）
- **验证**：**已实现**（默认关闭，因 Gazebo TurtleBot3 无电量话题）；补充温度判定

## 9. 类别 4：指令与控制安全（CMD）

> 你的原始描述只有一句"对超出的范围进行拒绝"。这需要展开为**完整的指令准入与仲裁体系**：谁有权发指令、指令是否合法、指令是否可信、多个源冲突怎么办。

---

**`CMD-001` 指令范围校验**

- **等级**：`S2` / **强制**
- **触发**：指令的任一分量超出额定范围（见 `MOT-001`/`MOT-002`）
- **阈值**：`v_max = 0.22 m/s`，`ω_max = 2.84 rad/s`
- **响应**：**拒绝**该帧 + `CMD_OUT_OF_RANGE`（S2）→ `DEGRADED`
- **恢复**：指令回到范围
- **依据**：ISO 10218-1:2025 速度限制（PL d）
- **验证**：边界值测试（恰好在限值、限值 +ε）

**`CMD-002` 拒绝而非截断（语义规则）**

- **等级**：`S1` / **强制**
- **触发**：不适用（设计约束）
- **响应**：超限/非法指令**不得**被静默截断后放行；必须**拒绝并告警**。唯一例外：`COL-006` 的动态限速，其限速值必须**回传给上层**（否则上层以为指令已生效，造成 `CMD-011` 隐性不一致）
- **依据**：静默截断破坏"控制器—执行器"一致性假设，是隐性失效来源
- **验证**：代码审查 + 断言门控输出与上报的限速值一致

**`CMD-003` 指令加速度/加加速度限制**

- **等级**：`S2` / **强制**
- **触发**：见 `MOT-003` / `MOT-005`
- **响应**：拒绝 + `CMD_ACCEL_EXCEED`（S2）
- **恢复**：恢复正常
- **验证**：阶跃指令测试

**`CMD-004` 指令时间戳有效性**

- **等级**：`S3` / **强制**
- **触发**：指令携带的 `stamp` 来自未来（`> now + 0.5 s`）或过于陈旧（`> T_cmd_max_age = 1.0 s`）
- **阈值**：`T_cmd_max_age = 1.0 s`
- **响应**：`CMD_STAMP_INVALID`（S3）→ 丢弃该指令 + 保护停（若无其他有效指令源）
- **恢复**：有效指令到达
- **依据**：过期指令重放是典型的危险场景（尤其 bag 回放、网络重传）
- **验证**：注入陈旧时间戳指令，断言被丢弃

**`CMD-005` 指令源唯一性与仲裁**

- **等级**：`S4` / **强制**
- **触发**：`T_arb = 200 ms` 内检测到**多于一个**独立的非零指令源
- **阈值**：`T_arb = 200 ms`；指令源由 `node name` / 话题 / 消息内标识区分
- **响应**：**保护停** + `CMD_MULTIPLE_SOURCES`（`S4`）→ `SAFE_STOP`（多源冲突意味着控制权不明，任何一方都可能与另一方对抗）
- **恢复**：恢复单源 + 人工确认
- **依据**：ISO 13849-1（避免非确定性控制）；实际项目中最常见的事故成因
- **验证**：同时启动 teleop 与导航，断言冲突检出

**`CMD-006` 控制权显式声明**

- **等级**：`S2` / **强制**
- **触发**：无人持有控制权（无有效 `source` 标识）
- **阈值**：控制权标识字段
- **响应**：拒绝无主指令 + `CMD_NO_AUTHORITY`（S2）
- **恢复**：显式取得控制权
- **依据**：ISO 10218-1:2025 启动联锁 / 使能功能（enabling function，默认 **PL d**）
- **验证**：发送无标识指令，断言被拒

**`CMD-007` 指令看门狗（心跳）**

- **等级**：`S3` / **强制**
- **触发**：`motion_expected == true` 且指令源静默 `> T_cmd_wd = 500 ms`
- **阈值**：`T_cmd_wd = 500 ms`（**显著短于现有 `timeout.cmd_vel_sec = 1.0`**）
- **响应**：`COMMAND_STALE`（现有告警码，S3）→ 保护停（保持最后安全指令 ≤ 200 ms，随后归零）
- **恢复**：指令恢复 + 确认
- **依据**：指令通道丢失后若继续按最后指令运动，等于**开环盲走**
- **验证**：**已实现**（`COMMAND_STALE`）；需把超时从 1.0 s 收紧并补"保持 ≤200 ms"行为

**`CMD-008` 指令与平台能力匹配**

- **等级**：`S2` / **强制**
- **触发**：见 `MOT-004`
- **响应**：拒绝 + `CMD_INFEASIBLE`（S2）
- **依据**：避免积分饱和造成隐性不一致
- **验证**：不可达组合测试

**`CMD-009` 急停指令优先于一切**

- **等级**：`S4` / **强制**
- **触发**：收到急停指令 / 硬件回路断开
- **响应**：**立即**（≤ 100 ms）切断运动输出，**抢占所有其他指令**；`CMD_ESTOP`；该路径必须独立于常规指令通道
- **恢复**：人工复位 + 重启联锁
- **依据**：ISO 10218-1:2025 急停功能（默认 **PL c**）；但本平台急停应**高于**该默认值实现
- **验证**：在最大速度下触发急停，测停止时间与距离

**`CMD-010` 指令速率限制（防泛洪）**

- **等级**：`S2` / **强制**
- **触发**：指令到达率 `> f_cmd_max`
- **阈值**：`f_cmd_max = 100 Hz`（高于此值会挤占控制周期）
- **响应**：限流 + `CMD_FLOOD`（S2）；丢弃超出部分并告警
- **恢复**：速率恢复
- **依据**：CPU 饥饿会导致安全任务超时
- **验证**：以 1 kHz 灌指令，断言限流且安全任务不受影响

**`CMD-011` 该动没动（指令—执行不一致）**

- **等级**：`S2` / **强制**
- **触发**：`command.valid == true` 且 `consistent == false`
- **阈值**：`tolerance_fraction = 0.5`（沿用）；持续时间 `> 1.0 s`
- **响应**：`COMMAND_MISMATCH`（现有，S2）→ `DEGRADED`；持续 3 s → 保护停
- **恢复**：一致持续 1.0 s
- **依据**：堵转、断轴、抱闸未释放、驱动器未使能
- **验证**：**已实现**（含 `valid`/`consistent` 三态设计——"无法判定"不得伪装成"不一致"）

**`CMD-012` 不该动却动了（异常运动）**

- **等级**：`S4` / **强制**
- **触发**：`motion_expected == false` 且 `|odom.speed| > 0.05 m/s` 持续 `T_unexpected = 500 ms`
- **阈值**：速度阈值 `0.05 m/s`（高于噪声底），`T_unexpected = 500 ms`
- **响应**：`UNEXPECTED_MOTION`（现有，`S4`）→ `SAFE_STOP`（这是**最危险**的一类失效：失控运动、指令残留、驱动器自走）
- **恢复**：需人工复位
- **依据**：ISO 13849-1；失控运动防护
- **验证**：**已实现**；补充"外力推动"与"指令残留"两种场景的区分测试

## 10. 类别 5：定位安全（LOC）

> 你的三条（Position jump / timeout / invalid）方向正确。需要补充的是第 4 条——**"定位还活着，但悄悄漂移了"**。这是定位失效中最隐蔽、也是实际事故中最多见的一种：`/amcl_pose` 以 10 Hz 正常发布、协方差看起来正常，但位姿已经偏离真实位置数十厘米。单一的"超时"与"合法性"检查永远抓不到它。

---

**`LOC-001` 位姿跳变检测**

- **等级**：`S4` / **强制**
- **触发**：相邻两帧位姿间 `Δp = √(Δx² + Δy²) > Δp_max`，且跳变隐含速度 `Δp/Δt > v_jump_max`
- **阈值**：`Δp_max = 0.50 m`（单帧）；`v_jump_max = 2.0 m/s`（远高于 `v_max`，故物理上不可能）
- **响应**：`LOC_POSITION_JUMP`（`S4`）→ `SAFE_STOP`（位姿跳变会使所有基于地图的避障与路径判断失效）
- **恢复**：定位重新收敛并稳定 2.0 s + 人工确认
- **依据**：物理可达性约束（`v_max` 是硬边界）；AMCL 重定位/粒子收敛是典型诱因
- **验证**：注入单帧 1.0 m 跳变，断言触发；同时验证真实快速运动（`0.22 m/s × 0.1 s = 0.022 m`）不误报

**`LOC-002` 偏航跳变检测**

- **等级**：`S4` / **强制**
- **触发**：`|Δψ| > ψ_jump_max` 单帧
- **阈值**：`ψ_jump_max = 30°`（`ω_max = 2.84 rad/s`，10 Hz 下物理上界 ≈ 16°）
- **响应**：`LOC_YAW_JUMP`（`S4`）→ `SAFE_STOP`
- **恢复**：同 `LOC-001`
- **依据**：同 `LOC-001`；偏航跳变对航向控制致命
- **验证**：同 `LOC-001`

**`LOC-003` 位姿协方差有效性**

- **等级**：`S3` / **强制**
- **触发**：`pose_cov > cov_critical`（`= 0.25 m²`，即 `σ ≈ 0.5 m`）
- **阈值**：`cov_warn = 0.05 m²`（S2）、`cov_critical = 0.25 m²`（S3）
- **响应**：`S2` → `DEGRADED` + 限速；`S3` → `PROTECTIVE_STOP` + `LOC_UNCERTAIN`
- **恢复**：协方差恢复 + 迟滞
- **依据**：不确定性过大时，基于定位的决策不可信
- **验证**：现有 `POSE_UNCERTAIN` 基础上扩展分级

**`LOC-004` 位姿数值合法性**

- **等级**：`S3` / **强制**
- **触发**：位姿为 `NaN`/`inf`；或位于地图边界外；或 `z` 偏离地面 `> 0.5 m`
- **响应**：`LOC_POSE_INVALID`（S3）→ 保护停
- **恢复**：合法位姿 + 确认
- **依据**：见 `SEN-011`（NaN 陷阱）
- **验证**：注入 NaN 位姿

**`LOC-005` 定位超时**

- **等级**：`S3` / **强制**
- **触发**：定位源静默 `> timeout_loc`
- **阈值**：`timeout_loc = 3 × T_loc_period`（AMCL 10 Hz → 0.3 s；**不得**沿用 1.0 s 这类宽松值）
- **响应**：`LOC_TIMEOUT`（S3）→ 保护停
- **恢复**：定位恢复 + 稳定 + 确认
- **依据**：无定位则无法保证路径与避障正确（AMR 中定位是安全相关输入）
- **验证**：停掉定位节点，断言保护停

**`LOC-006` 定位与里程计的一致性**

- **等级**：`S2` / **强制**
- **触发**：窗口 `T_loc_xcheck = 2.0 s` 内，`|Δp_loc − Δp_odom| > d_tol`
- **阈值**：`d_tol = max(0.10 m, 0.3 × |Δp_odom|)`
- **响应**：`LOC_ODOM_DIVERGENCE`（S2）→ `DEGRADED` + 限速；持续 → `S3`
- **恢复**：一致持续 2.0 s
- **依据**：定位漂移的**主判据**；里程计短期可信，长期漂移，两者偏差直接反映定位质量
- **验证**：注入定位缓慢漂移（0.1 m/s），断言 2 s 内触发

**`LOC-007` 定位更新停滞（活着但不更新）**

- **等级**：`S4` / **强制**
- **触发**：定位源**持续发布**但 `pose` 数值**完全不变**（`max−min < 1e-9`）超过 `T_loc_frozen = 1.0 s`，**且** `motion_expected == true`
- **阈值**：`T_loc_frozen = 1.0 s`
- **响应**：`LOC_FROZEN`（`S4`）→ `SAFE_STOP`
- **恢复**：位姿恢复更新 + 人工复位
- **依据**：**这是 `SEN-001` 超时检测抓不到的失效**——话题正常、频率正常、字段合法，只有数值被冻结。与 `SEN-003` 同源，但定位冻结的后果更严重
- **验证**：冻结位姿输出但保持发布，断言触发；并验证机器人静止时不误报

**`LOC-008` 定位置信度/匹配质量**

- **等级**：`S2` / **条件**（成立条件：定位器提供置信度或匹配分数，如 AMCL 的粒子权重、NDT 的匹配得分）
- **触发**：置信度 `< conf_min` 或匹配得分 `< score_min` 持续 `T_conf = 1.0 s`
- **阈值**：按定位器标定；`conf_min` 取"正常导航时置信度分布的第 5 百分位"
- **响应**：`LOC_LOW_CONFIDENCE`（S2）→ `DEGRADED` + 限速；持续 5 s → 保护停
- **恢复**：置信度恢复
- **依据**：置信度是先于位置误差暴露的早期指标
- **验证**：在特征稀疏区域运行，记录置信度并标定阈值

**`LOC-009` 定位漂移的长期监测（静默失效）**

- **等级**：`S3` / **强制**
- **触发**：以下**任一**或组合，在 `T_drift = 10 s` 窗口内：
  1. 回环/重访点位置偏差 `> drift_tol`（需要地图或路标）
  2. 两个独立定位源（如 AMCL 与轮式里程计+IMU 航迹推算）持续偏离 `> d_tol`
  3. 长期平均 `|Δp_loc − Δp_odom|` 单调增长
- **阈值**：`drift_tol = 0.10 m` per 10 s（即 0.01 m/s 漂移率）；超过 `0.30 m` → `S4`
- **响应**：`S3` → `PROTECTIVE_STOP` + `LOC_DRIFT_DETECTED`；`S4` → `SAFE_STOP`
- **恢复**：定位重新收敛（人工确认）
- **依据**：ISO 3691-4（定位/导航完整性）；**漂移是最隐蔽的定位失效**
- **验证**：注入渐变漂移，断言在超过 0.10 m/10 s 前触发

## 11. 类别 6：通信安全（COM）

> 你的问题"如果通信中断该如何"必须变成一张**明确的行为表**。核心原则：**通信中断不得让机器人处于"未知但继续运动"的状态**。同时必须区分"监控链路中断"与"控制链路中断"——两者的正确响应不同。

### 11.1 通信链路清单

| 链路 | 方向 | 丢失后果 | 正确响应 |
|---|---|---|---|
| 速度指令通道（`/cmd_vel`） | 上位机 → 机器人 | 机器人按最后指令盲走 | `CMD-007`：保护停 |
| 定位通道（`/amcl_pose`、TF） | 定位 → 规划/控制 | 基于定位的决策失效 | `LOC-005`：保护停 |
| 传感器通道（`/scan`、`/odom`、`/imu`） | 传感器 → 全栈 | 避障与状态判断失效 | `SEN-001`：保护停 |
| 远程监控/调度链路 | 机器人 ↔ 调度 | 失去远程监控与调度 | **降级但不停**（若本地安全功能完好） |
| 安全监控自身输出（`/robot_safety/...`） | 监控 → 状态机/门控 | 失去高级保护，但门控仍在 | `SYS-016`：门控看门狗 |
| 安全门控 → 驱动 | 门控 → 驱动 | **最严重**：失去最后防线 | 驱动侧看门狗 + 硬件使能线 |

---

**`COM-001` 关键通道看门狗**

- **等级**：`S3` / **强制**
- **触发**：关键通道静默超过各自超时（见 §11.1 与 `SEN-001`/`CMD-007`/`LOC-005`）
- **阈值**：每通道独立，见对应规则
- **响应**：按通道映射到保护停/安全停；**所有关键通道同时丢失** → `SAFE_STOP`
- **恢复**：通道恢复 + 稳定 + 确认
- **依据**：ISO 13849-1（诊断）；ISO 3691-4（通信失效）
- **验证**：逐通道断开测试（`tc netem` / 拔网线），断言响应正确

**`COM-002` 通信质量监测**

- **等级**：`S2` / **强制**
- **触发**：丢包率 `> loss_max`，或时延 `> lat_max`，或抖动 `> jitter_max`
- **阈值**：`loss_max = 5%`，`lat_max = 100 ms`，`jitter_max = 50 ms`（按实际链路标定）
- **响应**：`COM_QUALITY_DEGRADED`（S2）→ `DEGRADED` + 限速（为潜在中断预留裕量）
- **恢复**：质量恢复持续 2.0 s
- **依据**：质量下降先于完全中断；提前降级可避免"运动中突然失联"
- **验证**：注入 10% 丢包，断言降级

**`COM-003` 链路冗余与心跳**

- **等级**：`S3` / **条件**（成立条件：安全功能依赖该链路）
- **触发**：主链路丢失
- **阈值**：心跳周期 `T_hb = 100 ms`，丢失 `3 × T_hb` 判定断链
- **响应**：切换备用链路（若存在）；无备用则按 `COM-001`
- **依据**：ISO 13849-1 对 Cat 3/4 的冗余要求；单一通信路径**无法**达到 PL d
- **验证**：主链路断开测试

**`COM-004` 分离/失联行为定义（核心规则）**

- **等级**：`S3` / **强制**
- **触发**：远程监控/调度链路丢失
- **阈值**：`T_link_loss = 1.0 s`（可配置）
- **响应**（**必须显式配置其一，不得留空**）：

| 选项 | 行为 | 适用 |
|---|---|---|
| `STOP_LOCAL` | 立即保护停 | **默认**，无人员/流程依据时唯一可接受选项 |
| `CONTINUE_MISSION` | 继续执行当前任务至完成点 | **仅在**风险评估明确支持，且本地安全功能齐全时可接受 |
| `RETURN_HOME` | 以限速返回预设安全点 | 有明确安全停靠点且路径风险已评估 |

- **恢复**：链路恢复 + 按选项确认
- **依据**：ISO 3691-4（通信中断行为）；**"未定义"本身就是缺陷**——失联时不得依赖操作员临时判断
- **验证**：断开调度链路，断言按配置行为执行

**`COM-005` 命令通道丢失时的安全保持**

- **等级**：`S3` / **强制**
- **触发**：`CMD-007` 触发
- **阈值**：安全保持窗口 `T_hold = 200 ms`（**远短于** `T_cmd_wd = 500 ms`）
- **响应**：保持最后**有效**指令 ≤ 200 ms（避免急停带来的机械冲击），随后**归零并保护停**
- **依据**：平衡"平稳停车"与"不盲走"；保持窗口必须短于停止距离裕量允许的时间
- **验证**：断开指令源，测量实际停车延迟

**`COM-006` 安全功能不依赖非安全链路**

- **等级**：`S4` / **强制**（架构约束）
- **触发**：检测到安全判定输入来自非安全通道（普通 Wi-Fi、非安全 DDS 主题、无 QoS 保证的订阅）
- **响应**：该输入**不得**单独用于触发或解除安全状态；仅可作为附加信息。违反时判定为架构缺陷 + `COM_UNSAFE_DEPENDENCY`（设计审查项）
- **依据**：ISO 13849-1；INV-3
- **验证**：架构评审 + 依赖图检查

**`COM-007` 通信超时的墙钟基准**

- **等级**：`S2` / **强制**
- **触发**：不适用（实现约束）
- **响应**：所有通信超时**必须**基于墙钟（`steady_clock` 单调时钟优先），不得基于 ROS 时间或消息时间戳
- **依据**：INV-4；仿真暂停、rosbag 回放会伪造"新鲜"
- **验证**：暂停仿真，断言仍判定为超时（现有实现已正确处理）

**`COM-008` 重连后的安全复位**

- **等级**：`S4` / **强制**
- **触发**：通信恢复
- **响应**：**不得**自动恢复运动；必须经过重启联锁与人工确认（与 §3.2、`SYS-018` 一致）
- **依据**：ISO 10218-1:2025 重启联锁；自动恢复会造成"通信抖动 → 反复启停 → 二次碰撞"
- **验证**：反复通断链路，断言每次恢复都需确认

**`COM-009` 时间同步**

- **等级**：`S2` / **条件**（成立条件：多节点需要跨机时间对齐，如轨迹或日志关联）
- **触发**：节点间时钟偏差 `> sync_tol = 50 ms`
- **响应**：告警 + 禁用跨节点时序判定（避免用不可对齐的时间做安全判断）
- **依据**：跨机时序判定在时钟未同步时无意义
- **验证**：注入时钟偏移

**`COM-010` 消息新鲜度与重放防护**

- **等级**：`S3` / **强制**
- **触发**：收到序号回退或重复的消息（重放）
- **阈值**：序号单调性检查；重放窗口 `> 1.0 s`
- **响应**：丢弃 + `COM_REPLAY_DETECTED`（S3）→ 保护停（若为关键通道）
- **依据**：重放攻击/软件缺陷会重放历史安全指令（如"前进"）
- **验证**：重放历史 `/cmd_vel`，断言被拒

## 12. 类别 7：系统完整性与看门狗（SYS）

> 你把第 7 类也写成了"通信安全"（与第 6 类重名，应为"系统完整性"）。"如果系统本身损坏"是目前**最单薄**的一条，但它恰恰是功能安全的核心——ISO 13849-1 整本标准都在讲**如何让系统在自身故障时仍然安全**。

---

**`SYS-001` 掉电与欠压安全行为**

- **等级**：`S4` / **强制**
- **触发**：主电源 `V < V_min_cutoff`，或电池进入深度放电
- **阈值**：`V_min_cutoff` 按电池组标定（留出 ≥ 500 ms 制动能量）
- **响应**：`SYS_POWER_LOSS`（`S4`）→ 受控制动停车（利用剩余储能），而非自由滑行；抱闸（若有）在停止后释放/保持
- **恢复**：供电恢复 + 人工复位
- **依据**：IEC 60204-1 停止类别；**掉电会同时摧毁所有软件保护，必须由硬件/储能兜底**
- **验证**：满载运行中切断电源，测停止距离并确认未失控

**`SYS-002` 急停回路（硬件）**

- **等级**：`S4` / **强制**
- **触发**：急停按钮按下 / 安全回路断开
- **响应**：**硬件**切断电机使能，≤ 100 ms；软件急停作为冗余。停止类别按 IEC 60204-1 选择（建议 Category 0 或 1，取决于机械冲击容忍度）
- **恢复**：物理复位 + 重启联锁
- **依据**：ISO 10218-1:2025 急停（默认 PL c，本平台应更高）；**急停必须独立于软件**
- **验证**：满载急停测试；软件挂起时急停仍有效

**`SYS-003` 安全状态机看门狗**

- **等级**：`S4` / **强制**
- **触发**：状态机主循环停滞 `> T_wd_sm = 300 ms`，或状态机进程退出
- **阈值**：`T_wd_sm = 300 ms`（约为 `T_ctrl` 的 3 倍）
- **响应**：外部看门狗（独立进程/硬件）触发保护停
- **依据**：ISO 13849-1（看门狗是基础诊断措施）
- **验证**：`SIGSTOP` 状态机进程，断言看门狗触发

**`SYS-004` 监控节点看门狗**

- **等级**：`S3` / **强制**
- **触发**：`robot_safety_monitor` 停止发布 `> T_wd_mon = 500 ms`
- **响应**：**不得静默降级**——门控应转入保守模式（限速或保护停），而非"没有告警就是安全"
- **依据**：INV-1；**"监控挂了"绝不能被解释为"一切正常"**
- **验证**：kill 监控节点，断言进入保守模式

**`SYS-005` 安全门控看门狗（最后防线）**

- **等级**：`S4` / **强制**
- **触发**：门控进程本身停滞，或门控未在 `T_gate = 200 ms` 内更新输出
- **响应**：**驱动侧**独立看门狗判定指令流中断 → 电机失能（**不依赖任何上位软件存活**）
- **依据**：INV-1；安全链路最末端必须自治
- **验证**：kill 门控进程，断言电机失能

**`SYS-006` 进程崩溃与自动重启策略**

- **等级**：`S3` / **强制**
- **触发**：任一安全相关节点异常退出
- **响应**：记录 + 保护停；重启**不得**自动恢复运动（须经重启联锁）。重启频率限制（如 3 次/分钟）防止崩溃循环
- **依据**：ISO 10218-1:2025 重启联锁
- **验证**：反复 kill 节点，断言不会自动恢复运动

**`SYS-007` CPU/内存/实时性监测**

- **等级**：`S2` / **强制**
- **触发**：控制循环抖动 `> 20 ms`，或 CPU 占用 `> 80%` 持续 5 s，或内存占用持续增长
- **阈值**：`jitter_max = 20 ms`，`cpu_max = 80%`
- **响应**：`SYS_RESOURCE_STRESS`（S2）→ `DEGRADED` + 限速；持续 → 保护停
- **依据**：资源饥荒 → 安全任务超时 → 隐性失效
- **验证**：施加 CPU 负载，断言降级

**`SYS-008` 信号与时钟异常处理**

- **等级**：`S3` / **强制**
- **触发**：`SIGSEGV`/`SIGABRT`，或系统时钟被向后调整 `> 1.0 s`
- **响应**：安全停 + 崩溃转储；时钟跳变时改用单调时钟继续判定
- **依据**：同 `SEN-012`
- **验证**：注入时钟跳变

**`SYS-009` 电机过流/堵转**

- **等级**：`S3` / **强制**
- **触发**：电机电流 `> I_max` 持续 `T_i = 300 ms`，或电流高而轮速≈0（堵转特征）
- **阈值**：`I_max` 按电机额定（TurtleBot3 的 Dynamixel 可读电流/负载）；堵转判据：`|I| > 0.7·I_max` 且 `|ω_wheel| < 0.01 rad/s` 且 `motion_expected`
- **响应**：`SYS_MOTOR_OVERCURRENT` / `SYS_MOTOR_STALL`（S3）→ 保护停，防止过热与机械损坏
- **恢复**：电流恢复 + 确认
- **依据**：机械/电气完整性；堵转是 `CMD-011` 的根因之一
- **验证**：机械卡住车轮并下发运动指令，断言触发

**`SYS-010` 驱动打滑检测**

- **等级**：`S2` / **强制**
- **触发**：轮速积分位移与里程计位移偏差 `> slip_tol`（与 `SEN-009` 联动），或 IMU 加速度与轮加速度矛盾
- **阈值**：`slip_tol = max(0.10 m, 0.3 × 里程计位移)` per 2 s
- **响应**：`SYS_WHEEL_SLIP`（S2）→ `DEGRADED` + 限速（打滑时里程计不可信，停止距离核算失真）
- **依据**：定位与速度估计完整性
- **验证**：光滑地面加速测试

**`SYS-011` 电机/驱动过热**

- **等级**：`S3` / **强制**
- **触发**：电机或驱动温度 `> T_warn`（S2）/ `> T_crit`（S3）
- **阈值**：`T_warn = 60 °C`，`T_crit = 75 °C`（按器件手册标定）
- **响应**：`S2` → 降速；`S3` → 保护停 + `SYS_OVERTEMP`；需冷却后确认
- **依据**：热失效防护；过热后驱动器行为不可预测
- **验证**：持续高负载运行至温度阈值

**`SYS-012` 编码器/传感器硬件故障**

- **等级**：`S3` / **强制**
- **触发**：编码器读数跳变、丢步、方向反号；或驱动内部故障标志置位
- **响应**：保护停 + `SYS_ENCODER_FAULT`
- **依据**：底层传感完整性；错误的反馈比无反馈更危险
- **验证**：注入编码器异常序列

**`SYS-013` 启动自检（POST）**

- **等级**：`S4` / **强制**
- **触发**：上电 / 每班次启动
- **响应**：检查所有传感器、通信、门控、急停回路、制动、电池；任一失败 → 不得进入 `NORMAL`
- **依据**：ISO 10218-1:2025 启动联锁；**未经确认的系统不得进入可运动状态**
- **验证**：逐项注入故障，断言拒绝启动

**`SYS-014` 时间基准与单调性**

- **等级**：`S2` / **强制**
- **触发**：墙钟被调整；或 `time.time()` 与 `time.monotonic()` 差值异常
- **响应**：所有超时/窗口计算改用单调时钟 + `SYS_CLOCK_ANOMALY`
- **依据**：INV-4
- **验证**：在运行中调整系统时间，断言计时不受影响

**`SYS-015` 日志与可追溯性**

- **等级**：`S1` / **强制**
- **触发**：任何状态迁移 / 告警 / 安全动作
- **响应**：记录时间戳（单调 + 墙钟）、触发规则 ID、触发值、阈值、采取的动作、恢复时间；环形缓冲 + 持久化，防止掉电丢失
- **依据**：ISO 13849-1（验证与故障诊断）；事故调查的唯一依据
- **验证**：审计日志完整性

**`SYS-016` 安全参数完整性校验**

- **等级**：`S3` / **强制**
- **触发**：安全阈值参数被修改为不安全值、越界、或来源未经校验
- **响应**：拒绝加载 + `SYS_PARAM_INVALID`；**参数必须在启动时签名/校验和验证**，运行时不接受未经授权的修改
- **依据**：⚠️ 你的清单未覆盖——**参数被篡改（或配置错误）会静默解除所有保护**，而所有规则本身"配置正确"
- **验证**：注入越界参数（如 `v_max = 10`），断言拒绝加载

**`SYS-017` 安全软件版本与配置受控**

- **等级**：`S1` / **强制**
- **触发**：安全相关软件/配置版本变更
- **响应**：记录版本（`software_version` 字段已存在）；变更须走变更管理与回归测试
- **依据**：ISO 13849-1 第 4 章（安全生命周期管理）
- **验证**：版本可追溯性审计

**`SYS-018` 复位与重启联锁**

- **等级**：`S4` / **强制**
- **触发**：从 `SAFE_STOP`/`EMERGENCY_STOP`/`FAULT` 恢复
- **响应**：**必须显式人工动作**（按钮/受控远程指令）；恢复后先以 `DEGRADED` 低速运行确认，再进 `NORMAL`
- **依据**：ISO 10218-1:2025 重启联锁与复位；⚠️ 你的清单未覆盖
- **验证**：尝试自动复位，断言被拒

## 13. ISO 13849-1 功能安全分配

> 本节回答"每条规则要达到什么性能等级、什么架构、如何证明"。**规则描述了"做什么"，PL 决定了"做得多可靠"。** 没有 PL 分配的安全规则只是建议。

### 13.1 关键概念速览

**性能等级 PL**（a~e，PLe 最高）由四个参数经风险图确定：

```
               ┌─ S1 ── F1 ── P1 ─→ PLr = a
               │         F1 ── P2 ─→ PLr = b
  S1 ── F2 ── P1 ─→ PLr = b
               │         F2 ── P2 ─→ PLr = c
起点 ─┤
               ┌─ S1 ── F1 ── P1 ─→ PLr = b
               │         F1 ── P2 ─→ PLr = c
  S2 ── F2 ── P1 ─→ PLr = c
               │         F2 ── P2 ─→ PLr = d
```

- **S**（伤害严重度）：`S1` 轻微（通常可恢复）；`S2` 严重（通常不可逆，含死亡）
- **F**（暴露频率/持续时间）：`F1` 偶发且暴露时间短；`F2` 频繁或持续
- **P**（伤害避免可能性）：`P1` 在特定条件下可能避免；`P2` 几乎不可能避免

**架构类别 Category**（ISO 13849-1）：

| Cat | 结构 | 诊断 | 典型可达 PL |
|---|---|---|---|
| B | 单通道，无诊断 | 无 | — |
| 1 | 单通道，良好实践+经验证的元件 | 无 | c |
| 2 | 单通道 + 周期性测试 | 部分 | d |
| 3 | **双通道 + 诊断**（单一故障不导致安全功能丧失） | 高 | **d** |
| 4 | 双通道 + 持续诊断（故障累积也不丧失） | 很高 | e |

**本平台的风险图评估（建议，须由正式风险评估确认）**：

| 参数 | 取值 | 理由 |
|---|---|---|
| `S` | **S2** | 移动机器人（含负载可达数十 kg）撞人/夹人可致严重伤害甚至死亡，不可逆 |
| `F` | **F2** | AMR 通常长时间连续运行，人员暴露频繁 |
| `P` | **P2** | 差速底盘运行噪声低、速度可达 1 m/s 以上，且可能从背后接近，**几乎无法避免** |

→ `S2 + F2 + P2` ⇒ **PLr = d**

这与你引用的两本标准一致：ISO 10218-1:2025 对"保护性停止""降速"等安全功能给出默认 **PL d / SIL 2**；ISO 3691-4 同样要求安全相关功能达到 **PL d（Cat 3）**。

### 13.2 安全功能 × PL 分配表

| # | 安全功能 | 相关规则 | 目标 PL | 最低 Cat | 关键实现要求 |
|---|---|---|---|---|---|
| SF-01 | 安全停止（保护性停止） | `COL-002` `COL-005` `SEN-001` | **PL d** | **Cat 3** | 双通道：软件门控 + 硬件使能线 |
| SF-02 | 安全停止（安全/急停） | `SYS-002` `CMD-009` `SYS-018` | **PL d**（≥ 默认 PL c） | **Cat 3** | 硬件回路，独立于软件 |
| SF-03 | 速度限制 | `MOT-001`~`MOT-006` | **PL d** | Cat 3 | 需独立的速度监测通道（编码器/IMU 交叉校验） |
| SF-04 | 降速（场景自适应/SSM） | `MOT-007` `COL-006` `COL-014` | **PL d** | Cat 3 | 限速值必须回传上层（`CMD-002`） |
| SF-05 | 障碍/人员检测 | `COL-001`~`COL-004` `COL-013` | **PL d** | Cat 3 | 人员检测须用 **IEC 61496 安全激光雷达**，普通激光雷达不满足 |
| SF-06 | 安全方向控制 | `COL-010` `COL-011` | PL d | Cat 3 | 覆盖范围校验 |
| SF-07 | 静止/零速监测 | `MOT-008` `CMD-012` `COL-012` | **PL d** | Cat 3 | 独立于指令通道的运动检测 |
| SF-08 | 定位完整性 | `LOC-001`~`LOC-009` | **PL c**（建议 d） | Cat 2（建议 3） | 争议点：定位是"安全相关"还是"仅任务相关"取决于是否用于安全避障 |
| SF-09 | 通信完整性 | `COM-001`~`COM-010` | PL d | Cat 3 | 关键通道需冗余 + 心跳 + 序号 |
| SF-10 | 机器人使能/启动联锁 | `MOT-009` `SYS-013` `SYS-018` | **PL d** | Cat 3 | 同 ISO 10218-1:2025 使能功能默认值 |
| SF-11 | 系统完整性（看门狗/掉电） | `SYS-001`~`SYS-008` | **PL d** | Cat 3 | 独立看门狗 |
| SF-12 | 驱动完整性（过流/过热/编码器） | `SYS-009`~`SYS-012` | **PL c**（建议 d） | Cat 2 | 依赖驱动器内置诊断 + 上层校验 |
| SF-13 | 正常运行停止（Normal Stop） | `MOT-008` | **PL c** | Cat 2 | ISO 10218-1:2025 新增安全功能，与急停分离 |

> **PL d / Cat 3 的含义（务必理解）**：单一故障**不得**导致安全功能丧失；必须能用**诊断覆盖率 DC ≥ 90%**（中/高）检出故障；`MTTFd` 达"高"（≥ 30 年）；`CCF`（共因失效）得分 ≥ 65。
> **现实提醒**：单个 ROS 2 进程 + 单个普通激光雷达 + 单条 Wi-Fi 链路，**在结构上就达不到 Cat 3**。要达到 PL d 必须引入冗余或经认证的安全组件。这是本文件最重要的架构结论。

### 13.3 达成 PL d 的架构要求

| 要求 | 当前架构 | 差距 |
|---|---|---|
| 双通道停止路径 | 仅软件门控 | ❌ 需增加硬件使能线（安全继电器/安全 PLC） |
| 诊断覆盖率 DC ≥ 90% | 部分（超时、交叉校验） | ⚠️ 需量化 DC 并补齐 |
| 独立安全传感器 | 普通 2D 激光雷达 | ❌ 人员检测需 IEC 61496 安全激光雷达 |
| 通信冗余 | 单 Wi-Fi / 单 DDS | ❌ 需双通道或经认证的安全通信 |
| 看门狗独立于被监控对象 | 无 | ❌ 需独立看门狗（硬件或独立进程+独立电源域） |
| 参数完整性保护 | 无 | ❌ 见 `SYS-016` |
| 安全生命周期文档 | 无 | ❌ 见 §16 |

### 14.2 阈值标定原则

1. **能算的不猜**：停止距离、限速值用公式推导（§7.2），不靠经验值。
2. **每个阈值标注来源**：标准要求 / 制造商数据 / 实测标定 / 风险评估 —— 四者必居其一。
3. **标定必须记录条件**：地面材质、负载、轮胎磨损、电池电量都影响 `a_brake`。建议按最差条件取值（低摩擦、满载、低电量）。
4. **阈值变更受控**：见 `SYS-016`，安全阈值不得在运行时被修改。
5. **仿真与实物分开配置**：仿真中传感器频率与摩擦系数均不同，**不得**直接沿用阈值（`obstacle.critical_range_m` 已暴露此问题）。

### 14.3 必须先实测的三个量（否则规则无法正确工作）

| 量 | 方法 | 验收 |
|---|---|---|
| `T_ctrl`（控制时延） | 注入阶跃速度指令，用高速相机/编码器测指令到轮速变化的时间 | 记录 P95 值，写入配置 |
| `a_brake`（制动减速度） | 满速急停，测制动距离 `d`，反解 `a = v²/(2d)` | 取最差（最小）减速度 |
| 传感器实际频率与时延 | `ros2 topic hz` + 端到端时延测量 | 用于计算 `T_detect` |

### 15.4 三个必须立即修正的定量缺陷

> **缺陷 1（安全临界）**：`obstacle.critical_range_m = 0.15 m`，但仿真（5 Hz 激光）下 `S_stop ≈ 0.30 m`。
> **后果**：机器人会在触发保护停的**同时**已经撞上障碍物。
> **修正**：按 §7.2 重算，仿真设为 `≥ 0.36 m`。

> **缺陷 2（安全临界）**：`timeout.scan_sec = 1.0 s`，但激光实际 5 Hz（周期 0.2 s）。
> **后果**：允许连续丢失 5 帧扫描才报超时，这期间机器人"盲走"最多 0.22 m。
> **修正**：收紧至 `3 × 周期 = 0.6 s`；并联动 `COL-007` 扩大检测时延裕量。

> **缺陷 3（安全隐患）**：`timeout.imu_sec = 1.0 s` 对 100 Hz 的 IMU 过于宽松（允许丢失 100 帧）。
> **后果**：倾角判定（`MOT-010`）可能在 IMU 实际已失效 1 s 后才触发。
> **修正**：收紧至 `0.05 s`。

## 17. 假设、边界与未覆盖项

### 17.1 关键假设

1. **单机器人**：本规则集不处理多机器人协同避让（需独立的交通管理与死锁消解）。
2. **可控环境**：地面摩擦系数、坡度在标定范围内；超出（冰面、斜坡）会使 `a_brake` 失效，须加倍 `C_safety`。
3. **传感器安装正确**：激光水平、无遮挡、标定正确。倾斜或遮挡会使所有距离规则失效。
4. **人员不主动拆解**：不防护恶意破坏。防篡改见 `SYS-016`。
5. **速度上限 0.22 m/s**：基于 TurtleBot3 Burger 额定值。更换平台必须重新标定全部阈值。

### 17.2 已知残余风险

| 残余风险 | 缓解 | 残余等级 |
|---|---|---|
| 共因失效（单一激光雷达失效 + 软件同时失效） | 需硬件使能线冗余（未实现前不可接受） | **高** |
| 玻璃/镜面障碍不可见 | `COL-011` 部分缓解；需补充物理防护或 3D 传感器 | 中 |
| 人员从背后快速接近 | `COL-013`（若未部署安全激光雷达则无缓解） | **高** |
| 通信被恶意篡改 | `COM-010` 部分缓解；需 IEC 62443 | 中 |
| 定位在特征稀疏区缓慢漂移 | `LOC-009` 缓解 | 中 |

### 17.3 明确的未覆盖项

- 多机协同与交通管理
- 3D 障碍物检测（悬空物、地面凹陷、透明物）
- 负载动力学（未固定的负载可能移动重心）
- 室外环境（雨雪、强光、GNSS 失效）
- 消防/疏散联动
- 网络安全攻防（建议单独引用 IEC 62443）
- 机械本安设计（护栏、缓冲、防夹）
